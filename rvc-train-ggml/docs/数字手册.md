# 数字手册 —— 参数与训练日志里的每个数字

> 面向使用者：解释**输入参数**（bucket/T、disc_len、batch 等）与**训练日志/CSV 里的每个数字**
> 是什么意思、多大算正常、趋势代表什么。配合《使用指南》阅读；遇到报错先看其 §8 FAQ。

---

## 1. 输入参数里的数字

### 1.1 训练主参数

| 参数 | 单位/含义 | 典型值 | 说明 |
|---|---|---|---|
| `epochs` | 轮 | 20–200 | 一轮 = 把全部训练样本完整过一遍 |
| `batch`（B） | 个样本/步 | 1–2 | 一步同时喂给模型的样本数。**越大越吃内存**：B≥2 配大 T/d 容易撞 4096 MiB 单缓冲上限 |
| `bucket`（T） | **帧**（1 帧 ≈ 10 ms） | 200–384 | 训练图的时间长度上限。**帧数 ≤ T 的样本才会被训练**，超出的被跳过（日志 `skipped` 计数）。3.7 秒切片 ≈ 368 帧，所以 `T=384` 能覆盖全部官方切片；`T=300` ≈ 3 秒，会跳过更长的切片。T 越大越慢、越吃内存 |
| `disc_len`（d） | **采样点**（40k 采样率下 1 秒=40000） | 1024–12800 | 判别器每次看的生成波形长度。`0` = 用整段 segment_size（v1=12800，约 0.32 秒）。d 越大越慢、越吃内存，**对训练速度影响最大** |
| `grad_accum`（K） | 个 micro-batch | 1–8 | 梯度累积：累积 K 步再更新一次，**有效 batch = B × K**。想等效大 batch 但显存不够时的首选 |
| `steps` | 优化步 | — | 只跑 N 步就停（冒烟/试训用），优先于 `epochs` |
| `seed` | 整数 | 1234 | 随机种子：决定样本打乱顺序等。同 seed + 同配置 → 结果可复现 |
| `learning_rate` | 学习率 | 1e-4 | 官方默认；G/D 共用起点 |
| `log_interval` | 步 | 50 | 每多少个优化步往控制台/train.log 打一行 step 日志 |

**`segment_size`（不必填，config 内）**：训练时每次从样本里随机切的内部片段长度（v1=12800 采样点
≈ 0.32 秒 / 32 帧；v2=17280 / 36 帧）。它与 `bucket` 的区别：bucket 决定"图能装多长的样本"，
segment_size 决定"每次实际训练其中多长的一段"。

**内存/速度的粗规律**（实测口径，量级参考）：

- 显存/内存压力 ≈ 由 `T`、`d`、`B` 三者共同决定，**任一过大都会撞 4096 MiB 单缓冲硬限**（程序会明确报错）。
- 速度（秒/步）主要看 `T × d × B`。独显实测参考：`B=1/T=384/d=12800` 约 33–39 秒/步且 7 小时只跑了
  5 轮就崩（**不推荐**）；`B=2/T=300/d=4800` 稳定跑 70+ 轮。**不确定就从向导默认值（B=2/T=300/d=4800）开始。**

### 1.2 保存/导出参数

| 参数 | 含义 |
|---|---|
| `save_interval N` | 每 N 轮存一次可续训的 checkpoint（`train.ep{N}.ckpt.gguf`） |
| `export_every N` | 每 N 轮导出一次**可直接推理**的模型（`export.ep{N}.gguf`）——想"练一会儿就听一下效果"就设小，如 5 |
| `snapshot_keep N` | 快照保留数（0=全保留；设 3 则只留最近 3 份，省磁盘） |

## 2. 训练日志里的数字

### 2.1 启动行（最重要，先看这一行）

```
[trainer] 启动：bucket=384 batch=2 samples=92 skipped=0
          steps/epoch=46 epochs=50 max_steps=0 seed=1234（预计总优化步≈2300）
```

| 数字 | 含义 |
|---|---|
| `bucket / batch` | 你填的 T 和 B（回显，确认没填错） |
| `samples` | 缓存里**可训练**的样本数（帧数 ≤ bucket 的那些） |
| `skipped` | 因帧数 > bucket 被**跳过**的样本数。**不是 0 就说明 T 填小了**——部分数据没参与训练（可接受但要知情） |
| `steps/epoch` | 一轮的优化步数 = floor(samples ÷ batch ÷ grad_accum)（尾部不足一组丢弃） |
| `预计总优化步` | ≈ steps/epoch × epochs。用它 × 你的秒/步 = 预计总时长 |

### 2.2 step 行（每 log_interval 步一行）

```
[trainer] step 120 epoch 2 lr_g=9.975e-05 lr_d=9.975e-05
          loss_disc=1.834210 loss_gen_all=58.412211 loss_gen=1.204512
          loss_fm=9.871121 loss_mel=45.322104 loss_kl=2.014477
```

**6 项 loss 的含义**（`loss_gen_all` = 右边四项之和）：

| 名称 | 是什么 | 谁在优化它 |
|---|---|---|
| `loss_disc` | 判别器的 LSGAN 损失：区分"真声 vs 生成声"的能力误差 | 判别器 D（越小=分得越清） |
| `loss_gen_all` | **生成器总损失** = loss_gen + loss_fm + loss_mel + loss_kl | 生成器 G（整体指标） |
| `loss_gen` | 生成器的对抗损失：骗过判别器的误差 | G |
| `loss_fm` | 特征匹配损失：生成声与真声在判别器中间特征上的差距 | G |
| `loss_mel` | mel 频谱重建误差（L1）× **权重 c_mel=45**。**注意打印值已含 ×45**，所以它数值最大、主导 gen_all | G（**音质的主引擎**） |
| `loss_kl` | KL 散度 × 权重 c_kl=1：后验与先验分布的接近程度 | G |

**其他数字**：

| 数字 | 含义 |
|---|---|
| `step` | 总优化步数（一次 D 更新 + 一次 G 更新 = 1 步，与原版 `global_step` 同口径） |
| `epoch` | 当前轮（从 1 开始） |
| `lr_g / lr_d` | 当前学习率。每过一轮乘一次 `lr_decay`（默认 0.999875）——长训中缓慢变小属正常 |

### 2.3 epoch 汇总行（每轮结束一行）

```
[trainer] epoch 2 汇总 step=92 lr_g=9.975e-05 loss_disc=... loss_gen_all=...
```

该轮最后一个优化步的数值快照 + 本轮结束后的学习率。`epochs.csv` 每轮记一行，方便看轮间趋势。

### 2.4 结束/其他行

| 日志 | 含义 |
|---|---|
| `buf_g=xxxx.x MiB buf_d=xxxx.x MiB` | 生成器图 / 判别器图的缓冲大小。**单个不能超过 4096 MiB**，超限会直接报错（而不是慢） |
| `步时：首步=xxxx ms 均值=xxxx ms` | **首步偏慢是正常的**（首次分配/预热）；估算总时长用**均值** |
| `checkpoint 已保存: ...（step= epoch= lr_g=）` | 存档成功；括号内是续训恢复点 |
| `epoch N 已导出推理 GGUF: export.epN.gguf` | 可以拿这个文件去推理试听了 |
| `skipped=N`（启动行） | 见 §2.1，T 填小的信号 |

### 2.5 文件里的数字

| 文件 | 内容 |
|---|---|
| `train.log` | 人读版完整日志（与控制台相同） |
| `loss.csv` | **每个优化步一行**：`step,epoch,lr_g,lr_d,loss_disc,loss_gen_all,loss_gen,loss_fm,loss_mel,loss_kl`——用 Excel 拉折线图看趋势最方便 |
| `epochs.csv` | 每轮一行（同列），轮间对比用 |
| `run.json` | 本次运行的机器可读摘要（`--export-run-json` 开启时） |

## 3. 趋势判读：什么是正常，什么要警惕

### 3.1 正常现象（不用慌）

- **首步数值偏大、前几步波动剧烈**：初始随机状态 + 判别器未成型，属正常；看 10 步以后的趋势。
- **`loss_disc` 和 `loss_gen` 不单调、来回波动**：这是 GAN 的本质——两者在博弈中寻找平衡，
  **围绕某个区间震荡就是健康**。它们不是"越低越好"的指标。
- **`loss_mel` 缓慢、单调地下降**：这是**最可靠的进步指标**（音质主引擎）。几十步的尺度上看它。
- **`loss_kl` 先升后稳/缓降**：训练早期后验尚未对齐，属常见轨迹。
- **`lr_g/lr_d` 缓慢变小**：学习率衰减在工作。
- **首步很慢**：编译/预热，看均值。

### 3.2 健康训练的画像

- 所有 6 项**有限**（不是 `nan`/`inf`/巨大数）；
- `loss_mel` 整体缓慢下降，`loss_gen_all` 随之缓慢下降；
- `loss_disc`/`loss_gen` 在某个区间内震荡（比如各自在 0.5~5 之间跳）；
- 步时稳定，不随时间越来越慢。

### 3.3 要警惕的信号

| 信号 | 可能原因 | 处置 |
|---|---|---|
| 出现 `nan` / `inf` | 数值发散（F32 溢出） | 立即停止；减小学习率试一次；仍复现则把参数（T/d/B）和日志记录下来反馈 |
| `loss_gen` 持续上升 + `loss_disc` 趋近 0 | 判别器太强、压制生成器 | 通常伴随音质停滞；可减小 `disc_len` 或提前用当前导出试听（不少 checkpoint 仍可用） |
| `loss_mel` 不降反升、持续恶化 | 学习率过大 / 配置异常 | 停止；用默认超参重试 |
| `loss_gen_all` 在某次波动后永久飞出正常区间 | 训练炸了（同 nan 处置） | 从最近的 checkpoint 续训或重训 |
| `skipped` 占比很高（如 >20%） | bucket 太小，大量数据没参与 | 调大 bucket（注意内存），或接受只用较短样本训练 |
| 步时随训练越来越慢 | 内存/系统压力 | 减小 T/d/B；检查后台程序 |

### 3.4 数值量级参考（仅 sanity 用）

量级随数据与配置差异很大，**关注趋势比关注绝对值更重要**。粗略参考（v1-40k 默认权重 c_mel=45）：

- `loss_mel`（已 ×45）：初期几十到上百，随训练缓慢下降；
- `loss_fm`：个位数到几十；
- `loss_gen` / `loss_disc`：约 0.5~10 的区间内震荡（对抗平衡）；
- `loss_kl`：个位数附近。

如果你的数值长期偏离这些量级一个数量级以上且不收敛，按 §3.3 处置。

## 4. 常见换算速查

| 想知道 | 算法 |
|---|---|
| 一帧多长时间 | ≈10 ms（v1、v2 相同：hop = 采样率/100） |
| T=300 能训多长的样本 | ≈3.0 秒以内的切片（超过的跳过） |
| 一步吃多少样本 | batch × 1（grad_accum=K 时每 K 步合成一次"有效大 batch"更新） |
| 预计总时长 | 预计总优化步 × 均值步时（启动行 + 结尾步时行） |
| 一轮多少步 | floor(samples ÷ batch ÷ grad_accum)（就是启动行的 steps/epoch） |
| 现在练到哪了 | step ÷ (steps/epoch) = 当前轮；或看 step 行的 epoch 字段 |
| 4096 MiB 撞限了怎么办 | 减 T、减 d、减 B 任一；要等效大 batch 用 grad_accum |
