## 1. 总览

```
┌─────────────────────────────┐        ┌──────────────────────────────────────┐
│ rvc-prep.exe                │        │ rvc-train.exe                        │
│ 链接 rvc_core（ggml Vulkan）│        │ 链接 traincpp（Vulkan / CPU 调试）   │
│                             │        │                                      │
│ 原始音频 ──切片/重采样/高通──┼──缓存──▶ 数据集（bucket）──双图 G/D──AdamW──▶ │
│ f0(RMVPE) / HuBERT / 线性谱 │  文件  │ checkpoint（GGUF，可续训）          │
└─────────────────────────────┘        │ 导出器 ──▶ 推理 GGUF（rvc.*）        │
        （分进程，互不链接）           └──────────────────┬───────────────────┘
                                                          │
                                                  ┌───────▼────────┐
                                                  │ RVC-GGML.exe   │ 推理
                                                  │ ggml Vulkan    │
                                                  └────────────────┘

工具（Python，一次性转换/校验）：
  tools/pth_to_train_gguf.py  官方 .pth ──▶ 训练态 GGUF（微调/续训输入）
  tools/verify_train_gguf.py  训练态 GGUF 与源 .pth 对比校验
```

**为什么是两个 exe（关键决策）**

- `rvc_core` 依赖 ggml；`traincpp` 有自己的 Vulkan 后端。两个 Vulkan 后端在同一进程
  会造成设备/显存/驱动层面的共享与冲突风险，且双方都没有为对方设计过资源协调。
- 因此**进程级隔离**：预处理与训练是两个 exe，通过**文件缓存**交换数据；构建层面共用一个 CMake 工程。
- 后果：`rvc-prep` 不链 traincpp；`rvc-train` 不链 ggml/rvc_core。

## 3. 数据流

### 3.1 预处理（rvc-prep）

对齐原版 RVC 的 `train/preprocess.py` + `dataset/extract_f0.py` + `extract_hubert_feature.py`：

1. 读 WAV（dr_wav）→ 单声道 → 目标采样率（载入分支 = 自研 Kaiser 窗 sinc `resample_sinc`；
   16k 分支 = resampy `kaiser_best` 位级仿真 `resample_kaiser_best`；官方链路为 ffmpeg swresample，
   两侧不可逐样本一致 → 统计门）
2. 48Hz 高通：**官方因果 `scipy.signal.lfilter`（butter 5 阶、fs=目标采样率；filtfilt 已被官方注释停用）**
   → 集成侧自研（double；b/a 由 golden 对拍）；**不用** `rvc_core::dsp` 的 16k filtfilt
3. Slicer2 切片（`threshold=-42/min_length=1500/min_interval=400/hop_size=15/max_sil_kept=500`，
   精确复刻含 banker's rounding）→ 3.7s/3.4s 分块 + 峰值归一化 → 0_gt（F32）
4. 16k 分支（3.7s 块重采样；官方为 librosa kaiser_best/resampy → 统计门）：
   - RMVPE（`rvc_core::rmvpe`）→ f0 Hz → **无声帧 UV 线性插值**（官方 `np.interp`；无中值滤波）；
     粗量化 bins（mel 刻度 1..255、`np.rint`）→ f0bin
   - HuBERT（`rvc_core::hubert` 图结构；本项目自建执行器 `src/prep/feat.*`，绕开推理侧执行器的
     重复 compute 漂移缺陷）→ v1 final_proj(256) 或 v2 layer12(768)；输入为原始 16k 样本
     （不归一化、不 pad；帧数 `(L-400)//320+1`）
5. 线性谱缓存（pocketfft 主机侧，center=False + reflect pad `(n_fft-hop)/2`、周期 Hann、
   幅度 `sqrt(re²+im²+2e-7)`；训练口径，见 §5.3）
6. 写训练缓存（自定义格式，见 §5.2）与样本清单
7. 检索索引：特征（`.npy`/缓存）→ `index.gguf`（`--index` **默认完整 IVF**：
   置换 + 可选 MiniBatchKMeans + IVF k-means + list 分组；`--index-mvp` 回退单 list；`--search-index`
   搜索 dump），RVC-GGML 零改动加载

### 3.2 训练（rvc-train）

每个 step（对齐原版 `train/train.py:425-527`）：

1. 取 batch（phone/pitch/pitchf/spec/wave/sid + mask）
2. G 前向：`enc_p(phone,pitch)` → m_p/logs_p → `enc_q(spec)` → z → `flow(z)` → `rand_slice(z)` → `dec(z_slice, pitchf, g)`
3. `y_mel`（缓存谱切片，无梯度）与 `y_hat_mel`（可微 STFT，回流 G）
4. D 损失：`D(real), D(fake.detach())` → LSGAN → D 图反向 → `optim_d.step()`
5. G 损失：`D(real), D(fake)`（fmap）→ `loss_gen + fm + 45·mel + 1·KL` → G 图反向 → `optim_g.step()`
6. 每 epoch：`ExponentialLR.step()`；checkpoint；按策略导出推理 GGUF

训练循环（`src/train/trainer.*`）为单桶图（见 §8）、epoch 打乱（seed+epoch）/尾部丢弃、
G/D 各自 ExponentialLR 每 epoch 步进一次、`train.log`+`loss.csv`、checkpoint v2 双分区+共享 RNG。
save→load 往返已验证：A/B 存档后同一步 6 项 loss 逐位一致。

### 3.3 导出

实现：`src/export/model_gguf.{h,cpp}`（走 train.cpp `trc_gguf`，纯主机、编入 `rvc-train`）
+ CLI `rvc-train --export-gguf <in.train.gguf> --out <out.gguf>`。推理 GGUF（RVC-GGML schema）：
- 只导 `enc_p / flow / dec / emb_g`（滤 `enc_q.*`/`discriminators.*`）
- `weight_g/weight_v` → 折叠 `w = g·v/‖v‖` 后写 `weight`（标准 dim0 约定）
- Conv1d `[O,I,K]` → 展平 `(O, I*K)`；`dec.ups.*`（ConvT1d）不展平
- 写 `rvc.*` 元数据（version/sample_rate/has_f0/n_spk/inter_channels/.../conv_flat=true；`upsample_*` 必写）

导出正确性已对拍验证：与官方参考实现逐张量 max_abs ≤ 3.6e-7（全 F32）。

### 3.4 推理闭环

`rvc-train --export-gguf` → `RVC-GGML.exe --input ... --model export.gguf --noise-dir <确定性噪声>`。

实测参考（导出模型 F32，RVC-GGML 零改动）：严格 `--vits-selftest` corr=1.00000000 / SNR~100dB
（CPU+Vulkan）；端到端 CPU corr 0.99906、Vulkan 0.99897；导出产物与官方推理模型直接对拍
corr ≥ 0.9999。验收口径：①严格自检 corr≥0.999 ②导出端到端 ≡ 官方 ≥0.9999 ③CPU 端到端 ≥0.999。

### 3.5 训练↔推理兼容边界

- **模型语义基准 = 原版 RVC 运行时 `infer/lib/infer_pack/{models,modules,attentions,commons}.py`**
  （RVC-GGML 的验证基线）。官方训练仓库仅作训练循环/损失语义参考；其与运行时的唯一数学差异
  是 SineGen（训练侧用旧 `cumsum_shift` 法）。
- **主路径（发布）**：导出器写"折叠 weight_norm + Conv1d 展平（`dec.ups.*` 除外）+ `rvc.*` 元数据"，
  RVC-GGML **零改动**直接加载；`rvc.upsample_rates/kernel_sizes` 必写。
- **可选小改（训练中预览，已实施）**：RVC-GGML 直读训练态 GGUF，只动"文件读取层"
  （`RVC-GGML/src/gguf/gguf_model.{h,cpp}`）：
  - `load_weights` 末尾：`X.weight` 缺失且存在 `X.weight_g/weight_v` 时，在独立 ggml context +
    后备缓冲里分配 F32 `X.weight`（与 v 同形、不展平）并折叠；`weight()` 合并查主/折叠两个 context。
  - `meta_{u32,f32,bool,str,array_str,array_i32}`：`rvc.*` 未命中时回退 `rvc.train.*`。
  - **不触碰**：推理图/数值路径、SineGen、量化布局、架构名检查、非展平卷积路径
    （训练态 3D 权重本就支持）。
- **禁止**：以任何理由修改 RVC-GGML 的推理图/数值路径（含 SineGen 换成新法等）。

## 4. 权重链路

```
官方 .pth（G/D/预训练）
   │  tools/pth_to_train_gguf.py（一次性；保留 weight_g/v、enc_q、判别器）
   ▼
训练态 GGUF（traincpp ne 序；键名 = torch state_dict）
   │  src/model/weights.*（按名装载 + 形状校验）
   ▼
train.cpp Context 中的参数张量 ──首轮 forward/backward 对拍 & 训练──▶ checkpoint（GGUF）
   │
   └─ src/export/ ──▶ 推理 GGUF ──▶ RVC-GGML 推理
```

- 微调 = 装载预训练 G/D 后继续训练（`--pretrain-g/--pretrain-d`），机制与续训一致（只是初值不同）。
- 从零训练 = 不装载预训练，按 PyTorch 默认初始化（train.cpp `nn_init_*` 已对齐 PyTorch）。
- 训练态与推理态是**两套 GGUF**：前者保留 `weight_g/weight_v`，后者折叠/展平；不要混用。

### 4.1 训练态 GGUF schema（`rvc.train.*`）

由 `tools/pth_to_train_gguf.py` 写出（手工 GGUF v3，仅标准库+numpy/torch）；由
`src/model/weights.{h,cpp}`（TrainWeights）读取。

- 张量：名字 = torch `state_dict` 键名；`ne = reversed(torch.shape)`（标量记 `[1]`）；
  类型 F32（当前）或 F16；数据按 32 字节对齐、小端。
- 元数据（缺失字段读端记 0/空）：

| key | 类型 | 说明 |
|---|---|---|
| `general.architecture` | string | 恒 `"rvc-train"`（与推理 `rvc.*` 区分） |
| `general.name` | string | 输出文件主名 |
| `rvc.train.kind` | string | `G` / `D` |
| `rvc.train.version` | string | `v1` / `v2` |
| `rvc.train.has_f0` | bool | f0 / non-f0 |
| `rvc.train.form` | string | 源形态：`train`（model 键）/`small`（weight+config） |
| `rvc.train.source_pth` | string | 源 .pth 绝对路径（可追溯） |
| `rvc.train.out_dtype` | string | `F32` / `F16` |
| `rvc.train.tensor_count` | u32 | 张量数 |
| `rvc.train.sample_rate` | u32 | 32000/40000/48000 |
| `rvc.train.spec_channels` | u32 | `filter_length/2+1` |
| `rvc.train.filter_length` / `hop_length` / `win_length` | u32 | STFT 参数 |
| `rvc.train.n_mel_channels` / `mel_fmin` / `mel_fmax` | u32/f32 | mel 参数（fmax 为 null 时写 sr/2） |
| `rvc.train.segment_size` | u32 | 训练段长（小模型内嵌 config 可能为 0） |
| `rvc.train.inter_channels` / `hidden_channels` / `filter_channels` | u32 | 模型通道 |
| `rvc.train.n_heads` / `n_layers` / `kernel_size` | u32 | Transformer 参数 |
| `rvc.train.p_dropout` | f32 | dropout |
| `rvc.train.gin_channels` / `spk_embed_dim` / `upsample_initial_channel` | u32 | 其余模型参数 |
| `rvc.train.resblock` | string | `"1"` |
| `rvc.train.resblock_kernel_sizes` | i32[] | `[3,7,11]` |
| `rvc.train.resblock_dilation_sizes` | i32[] | 展平 `[1,3,5,1,3,5,1,3,5]` |
| `rvc.train.upsample_rates` / `upsample_kernel_sizes` | i32[] | 与 config 一致 |
| `rvc.train.d_periods` | i32[] | 仅 D：官方周期 v1 `[2,3,5,7,11,17]`、v2 `[...] ,23,37` |

> 注意：`spk_embed_dim` 以 `emb_g.weight.shape[0]` 实际值为准（与 config 不一致时警告）。
> 推理小模型（WebUI 提取的 .pth）无 `enc_q`（微调需用官方预训练 G/D 权重）。

## 5. 关键设计细节

### 5.1 图与内存

- 静态形状图：每个 bucket（序列长度）一套图；G、D 各一套/各分桶。
- 双图协议（train.cpp 验证过的形态）：
  - G 图：G 前向 → 输入 D 前向 A（D 冻结）→ G 损失；构建反向前 `param_list_set_param(d, false)`
  - D 图：D 前向 real + D 前向 fake（**新建节点**，不得复用 A 的节点）→ D 损失；构建前冻结 G
  - 步序：`graph_reset(gg)` → compute → `optim_step(g)`；`graph_reset(dg)` → compute → `optim_step(d)`
- 内存：优先 `buffer_alloc_graph_tensors`（图级 liveness 复用）；G 图先分配、D 图后分配（同 ctx 内共享张量跳过）；
  峰值不够时分 ctx 或 `buffer_free` + `context_release_graph_tensors`（元数据不回收）。
- 约束（train.cpp 已知语义）：
  - 同一张量不得出现在两个已构建反向的图中（构建期中止）
  - 共享中间量可跨图引用，但需在冻结侧不参与反向（needed 传播不包含）
  - 中间量 compute 后不可读（图级复用会覆盖），需要读的用旧 API
- **落地形态（`src/train/train_step.*`）**：**单 ctx 共享参数双图**
  （D 在 G 图冻结、D 图训练）——已证明单 ctx 可在 G 图分配→建 D 图→第二次分配；
  `set_batch`/`run_step` 四阶段步序。主机侧专用叶子（Ids/pitchf/噪声）不建张量、直接读文件；
  需 compute 后读的标量置 `TENSOR_FLAG_OUTPUT`。
- **回退方案（`src/train/train_step_selftest.cpp` 保留实现）**：两个独立 Context（ctx_g/ctx_d），
  D 参数在 ctx_g 里是冻结副本（权重名相同、对象不同 → 不触发多图共享守卫）；D 步结束后立即
  释放 ctx_d（并先快照 ΔW/梯度/loss），G 优化器状态在释放后分配——峰值更小，8GB 统一内存
  级核显可跑通。

### 5.2 训练缓存格式

原则：简单、可流式读、与 bucket 采样解耦、F32 小端、行主序；不追求兼容 Python 格式。
实现见 `src/prep/cache.{h,cpp}`（`write_cache_index`/`validate_cache`）、`src/prep/spec.{h,cpp}`；
CLI = `rvc-prep --exp DIR`、`--validate-cache DIR`。

```
<exp_dir>/
  dataset.json          # 缓存元信息 + 样本清单（见下）
  spec.json             # 字段字典（dtype/字节序/布局/推导公式）
  samples/
    <id>.gt.bin         F32 [gt_samples]        # target_sr，lfilter + 峰值归一化后（= 官方 0_gt 内容）
    <id>.16k.bin        F32 [frames16k]         # 16000Hz
    <id>.f0bin.bin      I32 [f0_frames]         # 粗量化 bins 1..255
    <id>.f0hz.bin       F32 [f0_frames]         # UV 插值后的连续 f0 Hz（全无声输入跳过）
    <id>.feat.bin       F32 [feat_frames, dim]  # HuBERT；dim=256(v1)/768(v2)，行主序（torch [T,C]）
    <id>.spec.bin       F32 [bins, spec_frames] # 行主序（torch [bins,T]）；v1-40k bins=1025
```

- `dataset.json` 关键字段：`format="rvc-train-cache"`, `format_version=1`, `target_sr`, `model_version`,
  `has_f0`, `per=3.7`, `overlap=0.3`, `slicer{threshold,min_length,min_interval,hop_size,max_sil_kept}`,
  `spec{n_fft,hop,win,bins}`, `f0{f0_bin,f0_min,f0_max}`，`samples[]` 每项：
  `{id, source, chunk, gt_samples, frames16k, f0_frames, feat_frames, feat_dim, spec_frames, spec_bins,
  files{gt,16k,f0hz,f0bin,feat,spec}}`；`id = <case>_<官方 idx1>`。
- 帧数推导（自检用）：`feat_frames = (samples16k - 400)//320 + 1`（HuBERT conv 前端无 padding，
  与 fairseq 一致，**不是** `ceil(samples16k/320)`）；
  `f0_frames = samples16k//160 + 1`（RMVPE `torch.stft(center=True)` 口径）；
  **`spec_frames = 1+(padded-n_fft)//hop`，`padded = gt_samples + 2*int((n_fft-hop)/2)`**
  （reflect pad + center=False；v1-40k 实测 = `gt_samples//hop`，3.7s 块 370）。
- 线性谱语义 = 官方 `spectrogram_torch`（2e-7 幅度、周期 Hann；与 §5.3 训练 mel 同口径）；
  实现 `compute_linear_spec` 用 pocketfft r2c（主机侧，非训练图）。
- 训练消费（`src/data/dataset.*`）对齐官方 `data_utils.py:84-97`：phone ×2、
  截到 `min(2*feat_frames,900)`，再与 spec 长度对齐截断；缓存存全量。

### 5.3 可微 STFT / mel 与损失

- `pad_ext(reflect)`（两侧 (n_fft-hop)/2）→ DFT 核折窗的 `conv_1d`（核 `[n_fft,1,2*BINS]`，
  cos/sin 分块）→ 拆 re/im → `sqr/add/sqrt` → `mul_mat(mel_basis)` → `clamp/log`
- DFT 核/滤波器组/ε 均为常量图张量（非 PARAM；分配后由 `stft_mel_fill_*` 填充）；
  复杂度 O(n_fft²·frames)
- **数值口径 = 官方 `train/mel_processing.py`**（训练侧）：periodic Hann、
  `center=False` + 显式 reflect pad、幅度 `sqrt(re²+im²+2e-7)`、`log(clamp(·, min=2e-6))`；
  与运行时 infer_pack 的 1e-6/1e-5 口径**不同**（勿混用）。对拍容差：前向 ≤1e-4、反向 ≤1e-3
- 落地：`src/train/stft_mel.{h,cpp}`（前向）+ `src/train/losses.{h,cpp}`（LSGAN D/G、
  feature matching×2、KL、c_mel·mel L1）+ `src/train/loss_selftest.{h,cpp}`（`--selftest-loss`）。
  实测参考（v1-40k-f0，CPU+Vulkan 各 81 项比较 0 失败）：spec 9.5e-7、mel 7.2e-7、
  自研 slaney 滤波器组 vs librosa 1.9e-9、损失/梯度 rel ≤3.5e-6

### 5.4 相对位置注意力

按 train.cpp《RVC 集成指南》§5.2 的组合：`conv_1d(1×1)` + `mul_mat`（batch 广播）+
`pad_ext/reshape/view/concat` 构造相对表与相对↔绝对变换；mask 用 `scores·M+(M−1)·1e4`
复刻 `masked_fill` 后再做普通 `soft_max`（`soft_max_ext` 的 `max_bias>0` 会触发 ALiBi，已禁用）。

### 5.5 精度与容差

- 全程 F32；golden 对拍容差：前向 ≤1e-4（相对）、反向 ≤1e-3、一步更新 ≤1e-4。
- **训练循环多步对拍**：首步硬门 ≤1e-4（实测 5.3e-7）；后续步因混沌放大，改用扰动探针系综
  包络作为容差上界（loss 必须有限）；端到端轨迹门 ≤1e-2。
- 推理闭环以"听感一致"为准：同噪声下 corr ≥0.999（对齐 RVC-GGML 验收口径）。

### 5.6 前向形状表（v1-40k-f0）

> 模型语义基准 = 原版 RVC 运行时 `infer/lib/infer_pack/{models,modules,attentions,commons}.py`
> （= RVC-GGML 验证基线；唯一数学差异是 SineGen，训练侧用旧法）。
> 约定：下文 torch 形状 `[B,C,T]`；写入 GGUF 时 `ne = reversed(shape)`。
> 配置：`inter=hidden=192, filter=768, heads=2, kernel=3, window=10, gin=256, up_init=512`；
> `upsample_rates=[10,10,2,2]`（乘积 400），`spec_channels=1025`；
> **模型内 `segment_size` = train.segment_size//hop = 12800/400 = 32 帧**（train.py:207/215）。

- `emb_g.weight [109,256]`；`g = emb_g(sid)[B,256]→unsqueeze(-1) [B,256,1]`。
- **enc_p**（TextEncoder）：
  - `phone [B,T,256]`（Linear 输入是最后一维 256）→ `emb_phone [B,T,192]`；
    `pitch [B,T]` I32 → `emb_pitch [B,T,192]`；相加 ×√192 → LeakyReLU(0.1) → 转置 `[B,192,T]`；
  - `x_mask [B,1,T]`；6 层：相对位置 MHA（q/k/v/o 1×1；heads view `[B,2,96,T]→[B,2,T,96]`，
    `scores/rel_logits [B,2,T,T]`，`emb_rel_k/v [1,21,96]`，window=10）+ Post-LN +
    FFN（conv1 `[768,192,3]`、conv2 `[192,768,3]`，padding 左 1 右 1，**ReLU**）+ Post-LN；
  - `proj [384,192,1]` → `stats [B,384,T] × x_mask` → `m_p/logs_p [B,192,T]`。
  - 注意：`modules.LayerNorm` 参数名是 **gamma/beta**（非 weight/bias）。
- **enc_q**（PosteriorEncoder）：
  - `spec [B,1025,T]` → `pre [192,1025,1]` × `y_mask [B,1,T]` → `[B,192,T]`；
  - WN：16 层 k5 d1；`cond_layer [6144,256,1]`（2·192·16=6144）→ 每层切 `[B,384,T]`；
    `in_layers.i [384,192,5]`、`res_skip_layers.i [384,192,1]`（最后一层 192）；全部 weight_g/v；
    `acts = tanh(x_in[:, :192]) * sigmoid(x_in[:, 192:])`；`x=(x+res[:192])*mask`，`output+=res[192:]`；
  - `proj [384,192,1]` × mask → `m_q/logs_q`；`z = (m_q + N(0,1)·exp(logs_q)) * y_mask`（noise 主机注入）。
- **flow**（训练**正向** `reverse=False`，flows 顺序 `[RCL0, Flip, RCL1, Flip, RCL2, Flip, RCL3, Flip]`）：
  - 每 RCL：`x0,x1=split(96)`；`pre [192,96,1]`；WN 3 层；`post [96,192,1]`（mean_only，m 即 stats）；
    `x1 = m + x1*exp(0)*x_mask`（训练正向即恒等缩放）；concat；Flip = **沿通道维** `torch.flip(x,[1])`；
  - 每步形状均 `[B,192,T]`。
- **rand_slice**（训练）：`rand_slice_segments(z, y_lengths, 32)` → `z_slice [B,192,32]`、`ids_slice [B]`；
  `slice_segments2(pitchf, ids_slice, 32)` → `pitchf_slice [B,32]`（**pitchf 帧率=100fps，与 z 帧对齐**）。
- **dec**（GeneratorNSF，f0 路径；`upp=400`）：
  - SineGen（**旧 `cumsum_shift` 法**，与 RVC-GGML `src/rvc/sinegen.cpp` 一致；噪声主机注入）→
    `har_source [B,1,12800]`（32×400）；`l_linear [1,1]`+tanh 在图内可训练；
  - `conv_pre [512,192,7]` → `[B,512,32]`；`+cond(g) [512,256,1]`；
  - 4 级：LeakyReLU(0.1) → `ups.i` ConvT1d（weight_g/v，`[I,O,K]`）：
    `[512→256,k16,s10,p3]→320`、`[256→128,k16,s10,p3]→3200`、`[128→64,k4,s2,p1]→6400`、
    `[64→32,k4,s2,p1]→12800`；加 `noise_convs.i`（conv_1d 作用在 har_source 上）：
    `[256,1,80] s40 p20`、`[128,1,8] s4 p2`、`[64,1,4] s2 p1`、`[32,1,1]`；
  - 每级 3×ResBlock1（ch=256/128/64/32，k=3/7/11，d=1/3/5；convs1/convs2 全 weight_g/v）取平均；
  - 末 LeakyReLU(**0.01**，`F.leaky_relu` 默认斜率) → `conv_post [1,32,7]`（无 bias）→ tanh → `o [B,1,12800]`。
- **判别器**（v1 MPD，f0D40k 权重）：S：k15s1p7 1→16；k41s4p20 g4 16→64；g16 64→256；g64 256→1024；
  g256 1024→1024；k5s1p2 →1024；conv_post k3s1p1 →1（fmap 7 项）；
  P(period)：`view [B,1,T/p,p]`（不足 reflect 右填充）→ 4×Conv2d k(5,1) s(3,1) p(2,0) 1→32→128→512→1024
  + 1×Conv2d s(1,1) → conv_post k(3,1) p(1,0) →1（fmap 6 项）；flatten(1,-1)。

## 8. 设计限制与后续方向

- **单桶图**：训练循环每个图使用单一 bucket（当前默认 `bucket=384`，超出样本跳过）；
  多桶图缓存需要 TrainStep 支持变 T 重建，暂缓，梯度累积（`train.grad_accum`）已实现。
- **导出精度**：导出 GGUF 当前首期为 F32；F16/量化档位策略为可选后续项。
- **长 T 反向**：resblock1 在超大 T（≥8192）下反向存在 F32 跨实现 kink 发散（非库缺陷，
  属数值边界），长 T 对拍采用统计口径；D 反向整图分配超 4 GiB 时依靠图级 liveness
  分配（`buffer_alloc_graph_tensors`）与分块控制。
- **向导交互**：交互式向导（`--interactive`）为推荐主 UX，后续按用户反馈调整。
