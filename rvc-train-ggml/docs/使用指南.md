# RVC-Train-GGML 使用指南

> 面向使用者：从**数据准备 → 训练（微调 / 从零）→ 导出 → 推理**的完整闭环。
> 覆盖 **v1-40k-f0 与 v2-48k-f0** 两套模型架构。
> **推荐新手直接用交互式向导（双击 exe 即可，见 §0.6）；命令行/脚本方式见各节，完全不受向导影响。**
> **训练规模（epoch/step 语义、一轮多少步）见 §3.6，试训前必读。**
> **参数与日志里每个数字的含义、趋势判读，见《数字手册》（docs/数字手册.md）。**

---

## 0. 总览与前提

### 0.1 三个可执行程序（务必分进程运行）

| 程序 | 职责 |
|---|---|
| `rvc-prep.exe` | 音频预处理：切片、16k、RMVPE f0、HuBERT 特征、线性谱、训练缓存、（可选）检索索引 |
| `rvc-train.exe` | 训练（微调 / 从零）、日志、checkpoint、续训、导出推理 GGUF |
| `RVC-GGML.exe` | 推理（变声/转换；加载导出的 GGUF 模型） |

> **rvc-prep 与 rvc-train 必须分两次运行**（两个 Vulkan 后端不能进同一进程）。
> 三个 exe 都在 `build\bin\`（或发布包根目录）；命令中的相对路径示例均以仓库/发布包根目录为工作目录。

### 0.2 运行要求与设备口径

- 平台：Windows 10/11 x64；显卡需支持 **Vulkan** 并装好显卡驱动（NVIDIA/AMD/Intel 均可）。
- **运行期零 Python、零 CUDA 依赖**；`vulkan-1.dll` 随显卡驱动提供。
- 设备下标因机器而异：用 `rvc-prep --list-devices` / `rvc-train --list-devices` 查看后选择。
  - **训练**：选 Vulkan GPU；CPU 仅作调试，**勿用于正式训练**（很慢）。
  - **预处理**：默认自动选 GPU；`--device 99` = CPU（慢，仅调试）。
- 长时间训练建议先设环境变量 `TRC_VK_CHUNK_NODES=64`（缓解部分独显驱动的
  `VK_ERROR_DEVICE_LOST`/Windows TDR 问题）：
  ```powershell
  $env:TRC_VK_CHUNK_NODES="64"
  ```
- train.cpp v0.4.0 起训练缓冲默认优先 **device-local**（独显真显存 + 共享 staging /
  可映射 device-local / host-visible 回退）；旧驱动或排查时可设
  `TRC_VK_HOST_MEMORY=1` 回退 host-visible。
- 单个大缓冲受 **Vulkan 单缓冲/存储范围硬限**（驱动而定，启动日志会打印实际值；常见 4096 MiB）：
  `batch ≥ 2` 配大 `bucket/disc_len` 可能超限失败；
  提高有效 batch 请用 `--grad-accum K`（见 §3.1/FAQ）。

### 0.3 Python 的定位

**训练与预处理运行期零 Python 依赖。** 唯一需要 Python 的场景：把官方 RVC 的预训练 `.pth`
**一次性**转换成训练态 GGUF（§1.2；需可运行 PyTorch 的 Python 环境）。从零训练和推理完全不需要 Python。

### 0.4 推荐入口：一键驱动脚本 `scripts\train_pipeline.ps1`

想用命令行一条龙时，可用这个**通用驱动脚本**：你自己决定音频目录、缓存目录、输出目录、模型与全部参数，
它把「预处理 → 训练 → 导出 →（可选）索引 / 闭环推理」串起来，并逐条打印实际执行的命令。

**从原始音频开始（自动预处理 + 微调 + 闭环推理）**：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\train_pipeline.ps1 `
  -Audio D:\myvoice -Work work\myvoice `
  -Mode finetune -G work\models\f0G40k.train.gguf -D work\models\f0D40k.train.gguf `
  -Epochs 50 -Bucket 384 -DiscLen 12800 -ExportEvery 5 -Device 1 `
  -Infer -InferInput D:\some\test.wav -InferModelDir models
```

**常用变体**：

```powershell
# 从零训练（随机初始化，无需 G/D）
... -Audio D:\myvoice -Mode scratch -Epochs 200

# 已有缓存，跳过预处理
... -Cache work\myvoice -SkipPrep -Epochs 50

# 断点续训（需配套 .meta.json）
... -Cache work\myvoice -Resume work\train_myvoice\train.ckpt.gguf -Epochs 80

# 只做预处理
... -Audio D:\myvoice -Work work\myvoice -PrepOnly

# 构建检索索引（推理检索用）
... -Cache work\myvoice -BuildIndex -IndexOut work\myvoice\myvoice.index.gguf

# 覆盖超参（未列出的高级项写进你自己的 -Config）
... -Cache work\myvoice -Lr 1e-4 -Seed 1234 -Beta1 0.8 -Beta2 0.99 -CMel 45 -CKl 1

# 先干跑看命令（不执行）
... -Cache work\myvoice -DryRun
```

关键参数（完整列表见脚本 `param` 块）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Audio` | — | 原始 wav 目录（触发 `rvc-prep`） |
| `-Cache` | — | 已有缓存目录（含 `dataset.json`；给出则跳过预处理） |
| `-Work` | `work\rvc_project` | `-Audio` 生成缓存的目录 |
| `-Out` | `work\train_<cache名>` | 训练输出目录 |
| `-Config` | `configs\v1-40k-f0.json` | 基础训练配置 |
| `-Mode` | `finetune` | `finetune`（需 `-G/-D`）/ `scratch` |
| `-G`/`-D` | — | 训练态权重（微调） |
| `-Sr`/`-Version`/`-HasF0` | `40000`/`v1`/`1` | 预处理目标采样率/版本/f0 |
| `-Hubert`/`-Rmvpe` | — | 预处理模型（`hubert.gguf`/`rmvpe.gguf` 路径） |
| `-PrepDevice` | `0` | rvc-prep 设备（0=Vulkan，99=CPU） |
| `-Device` | `1` | rvc-train 设备（Vulkan GPU；0=CPU 调试） |
| `-Epochs/-Batch/-Bucket/-DiscLen/-GradAccum` | `20/1/384/12800/1` | 训练主参数 |
| `-SaveInterval/-ExportEvery/-SnapshotKeep` | `1/1/0` | 快照/导出/保留 |
| `-Resume` | — | 续训 checkpoint（需 `.meta.json`） |
| `-BuildIndex`/`-IndexOut` | — | 构建检索索引 |
| `-Infer`/`-InferInput`/`-InferModelDir`/`-InferDevice`/`-Pitch`/`-Index`/`-IndexRate` | — | 闭环推理 |
| `-DryRun`/`-PrepOnly`/`-SkipPrep`/`-Export` | — | 控制开关 |

产物：`<Out>\`（`train.ckpt.gguf(+.meta.json)`、`train.ep{N}.ckpt.gguf`、`export.ep{N}.gguf`、
`loss.csv`/`epochs.csv`/`run.json`）；`-Infer` 时另有 `<Out>\converted.wav`。

### 0.5 拷贝到另一台机器训练

最小集拷贝即可（命令里的路径都支持**绝对路径**，不要求目录相对关系）：

- **必需**：`rvc-train.exe`（静态链接，运行期只依赖系统 `vulkan-1.dll`，随显卡驱动提供）。
- **微调时另需**：
  - 训练态权重 GGUF（如 `f0G40k.train.gguf` + `f0D40k.train.gguf`，v1；v2 为 `f0G48k`/`f0D48k`）；
  - 训练缓存目录（`rvc-prep` 产物的整个目录，含 `dataset.json`/`spec.json`/`samples\`）；
  - 训练配置（`configs\v1-40k-f0.json` 或 `configs\v2-48k-f0.json`）。
- 预处理可在任意机器完成；目标机只做训练时，拷 `rvc-train.exe` + 权重 + 缓存 + 配置即可。
- 到目标机先验证环境：`rvc-train.exe --selftest`（打印设备与计算自检）；
  长训建议设 `TRC_VK_CHUNK_NODES=64`（§0.2）。
- 小规模试训参数见 §3.1 与 §3.6。

### 0.6 交互式使用（推荐新手：双击即用）

两个程序都内置**中文向导**：**双击 exe（或在终端无参数运行）即进入向导**，逐项回答后开始工作。
退出前程序会显示"按回车键退出"，不会闪退（从 cmd/PowerShell/脚本启动则不暂停，不阻塞批处理）。
**命令行方式完全不变**（各节命令照常可用）。两个程序必须**分开运行**（§0.1），完整流程三步：

**第 1 步 —— 预处理（双击 `rvc-prep.exe`）**：

| 向导问题 | 填写说明 |
|---|---|
| 输入音频目录（或单个 wav 文件） | 你的原始 wav 目录（§2.1） |
| 预处理目标（1=v1-40k / 2=v2-48k） | 与训练用的模型版本一致 |
| RMVPE 权重路径 | RVC-GGML 模型目录下的 `rmvpe.gguf`（回车跳过 f0，**训练建议提供**） |
| HuBERT 权重路径 | `hubert.gguf`（**训练必需**；留空会警告"缓存不能用于训练"） |
| 训练缓存输出目录 | 默认 `work\cache_auto_40k` / `cache_auto_48k` |
| 计算设备下标 | 回车=自动（GPU）；`99`=CPU（慢，仅调试） |

确认后执行预处理；完成后**自动自校验**，打印样本数与"下一步：运行 rvc-train"提示。

**第 2 步 —— 训练（双击 `rvc-train.exe`）**：

| 向导问题 | 填写说明 |
|---|---|
| 数据入口（1=已有缓存 / 2=原始音频目录） | 1=填上一步的缓存目录；2=填原始音频目录，向导会**调用同目录的 rvc-prep.exe 帮你预处理**后继续 |
| 模型来源（1=微调 / 2=从零） | 微调需填 G/D 训练态 GGUF（§1.2）；从零不需要权重 |
| 输出目录 | 日志/checkpoint/导出目录；**若目录已有 checkpoint 会询问是否续训**（要求见 §3.4） |
| epochs / batch_size / bucket / disc_len | 默认 = **稳妥档 `batch=2 / bucket=300 / disc_len=4800`**；bucket>384 或 disc_len>6400 会触发**大配置代价警告**（大配置步时/显存开销高，建议先小规模试训，见 §3.6） |
| learning_rate / seed | 默认 `1e-4` / `1234` |
| 训练设备下标 | 向导会**列出设备**（名称/类型/显存）后让你选号；`-1`=自动 |
| 配置高级参数? (y/N) | 回车跳过；`y` 可设 grad_accum（梯度累积）/ save_interval / export_every / snapshot_keep / log_interval |

确认前程序打印**缓存信息**（样本数/版本/采样率）与**预计优化步/epoch**；缓存版本与模型配置不一致会
**警告**（训练会被预检拒绝）。确认后写 `<out>\train_config.json` 并直接开始训练。

**第 3 步 —— 推理**：用 §4 导出的 `export.ep{N}.gguf` 按 §5 命令在 `RVC-GGML.exe` 中推理。

**脚本化向导**（非交互批处理）：`rvc-prep --answers <文件>`、`rvc-train --interactive --answers <文件>`
（每行一个答案，顺序同提问）。

## 1. 一次性资产准备

### 1.1 预处理所需模型（随 RVC-GGML 发布/转换得到）

- `hubert.gguf`（HuBERT 特征）、`rmvpe.gguf`（f0）：放在 RVC-GGML 的 `models\` 目录
  （或你自己指定的任意目录，向导/命令行里填路径即可）。
- 推理用角色模型（如 `xxx.gguf`）与检索索引（`*.index.gguf`）：同上，仅推理用，训练不需要。

### 1.2 微调起点：官方预训练 `.pth → 训练态 GGUF`

微调（finetune）从官方 RVC 预训练权重出发：v1 用 `f0G40k.pth`（G）+ `f0D40k.pth`（D）；
v2 用 `pretrained_v2` 下的 `f0G48k.pth`/`f0D48k.pth`。

用一次性转换器（需要能运行 PyTorch 的 Python 环境；训练/推理运行期不需要 Python）转成**训练态 GGUF**：

```powershell
python tools\pth_to_train_gguf.py --pth <官方预训练>\f0G40k.pth `
    --config configs\v1-40k-f0.json --out work\models\f0G40k.train.gguf
python tools\pth_to_train_gguf.py --pth <官方预训练>\f0D40k.pth `
    --config configs\v1-40k-f0.json --out work\models\f0D40k.train.gguf
# 独立校验（可选；逐张量字节级 + CRC）
python tools\verify_train_gguf.py --pth <官方预训练>\f0G40k.pth `
    --gguf work\models\f0G40k.train.gguf --hashes work\models\f0G40k.hashes.txt
```

- v2 把 `--config` 换成 `configs\v2-48k-f0.json`、权重换成 f0G48k/f0D48k。
- `--kind auto|g|d`（默认 auto 推断）、`--dtype f32|f16`（默认 f32）、`--version v1|v2`、`--f0 0|1` 按需。
- 推理小模型（无 `enc_q`）不用于训练。

## 2. 数据准备（`rvc-prep`）

### 2.1 采集与放置音频

- 目标：**10–50 分钟**干净、单人、少混响的人声（训练质量主要取决于数据）。
- 采样率：与目标模型一致（v1-40k → `--sr 40000`；v2-48k → `--sr 48000`）。
- 放到一个目录（支持 `.wav`；也支持单个 wav），例如 `work\myvoice\`。

### 2.2 生成训练缓存

**推荐**：直接双击 `rvc-prep.exe` 走中文向导（见 §0.6 第 1 步）；命令行方式：

```powershell
build\bin\rvc-prep.exe --input work\myvoice --sr 40000 --version v1 --has-f0 1 `
    --exp work\cache_myvoice `
    --rmvpe models\rmvpe.gguf `
    --hubert models\hubert.gguf `
    --device 0
```

- `--input <dir|wav>`：音频目录或单个 wav。
- `--sr`：目标采样率（默认 40000）；`--version v1|v2` 决定 HuBERT 特征维度（v1=256 / v2=768）。
- `--has-f0 1`：f0 模型（本项目目标）；`--no-f0` / `--no-feat` / `--no-spec` 可关闭对应产物（一般不用）。
- `--per 3.7 --overlap 0.3`：官方分块参数（默认）。
- `--device 0` = Vulkan（默认）；`--device 99` = CPU（很慢，仅调试）。
- `--debug-dump <dir>`：可选，导出中间量原始数据（排查用）。

缓存产物（`work\cache_myvoice\`）：

```
dataset.json / spec.json
samples\<id>.gt.bin / .16k.bin / .f0hz.bin / .f0bin.bin / .feat.bin / .spec.bin
```

### 2.3 校验缓存

```powershell
build\bin\rvc-prep.exe --validate-cache work\cache_myvoice
```

### 2.4 （可选）构建检索索引（仅推理检索用，训练不需要）

RVC 的检索（`index_rate > 0`）属于**推理期**特性。若希望推理时启用检索混合，用缓存特征构建 `index.gguf`：

```powershell
build\bin\rvc-prep.exe --index --exp work\cache_myvoice --out work\index_myvoice\myvoice.index.gguf `
    --version v1 --seed 1234
build\bin\rvc-prep.exe --validate-index work\index_myvoice\myvoice.index.gguf
```

- 默认完整 IVF；`--index-mvp` 回退单 list；`--nprobe N` 写入检索 list 数（默认 1，可按 RVC-GGML 需要调整）；
  `--seed` 保证可复现。

## 3. 训练（`rvc-train`）

配置为自有 schema：顶层 `train` / `data` / `model` 三段（仓库自带 `configs/v1-40k-f0.json`、
`configs/v2-48k-f0.json`），额外可选 `run` 段。`rvc-train --train <config.json>` 可仅靠 `run` 段提供
`exp/out/pretrain_g/pretrain_d/device`，也可用 CLI 覆盖。

> 设备下标因机器而异：先 `rvc-train --list-devices` 查看；下文示例的 `--device 1` 表示
> "列表里的 Vulkan GPU"，CPU 下标（通常 0）仅调试。

### 3.1 微调（推荐先从这条路径开始）

```powershell
build\bin\rvc-train.exe --train configs\v1-40k-f0.json `
    --exp work\cache_myvoice `
    --weights work\models\f0G40k.train.gguf `
    --d-weights work\models\f0D40k.train.gguf `
    --out work\train_myvoice `
    --device 1 `
    --epochs 20 --batch 1 --bucket 384 --disc-len 12800 `
    --save-interval 1 --export-every 5
```

- `--weights`/`--d-weights`：微调起点（= `--pretrain-g`/`--pretrain-d`，别名）。
- `--epochs`：训练轮数；也可用 `--steps N` 限定总优化步数（冒烟/测试）。
- `--bucket`：图 T（须 ≥ `segment_frames`；样本超出桶会被跳过并在日志计数）。
- `--disc-len`：判别器输入长度（0 = 官方整段 `segment_size`；测试可设小值如 1024 提速）。
- `--grad-accum K`：梯度累积（有效 batch = batch × K）；**提高有效 batch 的首选**（B≥2 受 Vulkan 单缓冲/存储范围硬限，常见 4096 MiB）。
- `--save-interval N`：每 N epoch 存 `train.ep{N}.ckpt.gguf`（可续训）。
- `--export-every N`：每 N epoch 导出推理 GGUF `export.ep{N}.gguf`。
- `--snapshot-keep N`：epoch 快照保留数（0=全留）。
- `--export-run-json <path>`：写运行摘要 JSON（步时/内存/前几步 loss）。

### 3.2 从零训练

```powershell
build\bin\rvc-train.exe --train configs\v1-40k-f0.json `
    --exp work\cache_myvoice --out work\train_scratch_myvoice `
    --scratch --device 1 --epochs 200 --batch 1 --bucket 384 --disc-len 12800 `
    --save-interval 1 --export-every 10
```

- `--scratch`：按 config `data/model` 段生成随机初始化的 G/D（规格对齐官方 v1-40k），无需预训练权重。
- 与 `--weights/--pretrain-g` 互斥。**从零训练质量取决于数据量**，通常以微调为主。

### 3.3 交互式训练向导

**双击 `rvc-train.exe`（或无参数运行）即进入**；也可显式 `--interactive`：

```powershell
build\bin\rvc-train.exe --interactive
# 或提供基础配置 / 答案文件（便于脚本化）
build\bin\rvc-train.exe --interactive --config configs\v1-40k-f0.json --answers work\answers.txt
```

向导依次询问（直接回车采用 `[方括号]` 默认值；详细说明见 §0.6 第 2 步）：

1. **数据入口**：1=已有缓存目录 / 2=原始音频目录（向导调用同目录 `rvc-prep.exe` 预处理后继续；
   找不到 exe 时打印等价命令行）。
2. **模型来源**：1=预训练微调（填 G/D 训练态 GGUF）/ 2=从零训练。
3. （微调）**G / D 路径** → **输出目录**（已有 checkpoint 时询问**是否续训**）。
4. **epochs / batch_size / bucket / disc_len**——无基础配置时默认为**稳定档
   `batch=2 / bucket=300 / disc_len=4800`**（CLI/base config 传入的值优先）；大配置触发代价警告。
5. **learning_rate / seed / 设备**（设备先列清单再选号，`-1`=自动）。
6. **高级参数**（y/N，默认折叠）：grad_accum / save_interval / export_every / snapshot_keep / log_interval。
7. **确认前摘要**：缓存样本数/版本/采样率 + 预计优化步/epoch + 版本不一致警告 + 全部配置。
   确认后写 `<out>\train_config.json` 并**直接开始训练**。

### 3.4 断点续训

```powershell
build\bin\rvc-train.exe --train configs\v1-40k-f0.json `
    --exp work\cache_myvoice `
    --weights work\models\f0G40k.train.gguf --d-weights work\models\f0D40k.train.gguf `
    --out work\train_myvoice `
    --resume work\train_myvoice\train.ckpt.gguf `
    --device 1 --epochs 40
```

**续训的硬性要求**：

- checkpoint 必须与**同名旁挂元数据** `<ckpt>.meta.json` 一起存在（由训练自动写出）。缺 meta 会**报错拒绝**。
- 续训配置必须与存档**一致**：`batch_size / bucket / grad_accum / seed / segment_size / disc_len / lr /
  lr_decay / c_mel / c_kl / model 结构 / 数据维度` 等，以及**样本集**（样本数 + 总帧数 + id 列表）。
  任一不符会给出明确错误，**不做静默错位**。若要更换配置，请重新开始训练。
- 训练中随时可以 `Ctrl+C` 中断后用滚动 checkpoint（`train.ckpt.gguf`）续训；
  也可用 `--save-interval` 的 epoch 快照续训。

### 3.5 训练产物（`--out` 目录）

```
train.log / loss.csv / epochs.csv        # 逐步/每 epoch 日志
train.ckpt.gguf + train.ckpt.meta.json   # 收尾滚动 checkpoint（含续训元数据）
train.ep{N}.ckpt.gguf + .meta.json       # 每 N epoch 快照（--save-interval）
export.ep{N}.gguf                        # 每 N epoch 导出的推理 GGUF（--export-every）
train.ep{N}.snapshot.gguf                # 导出中间态（一般无需手动使用）
train_config.json                        # 仅向导模式写出
```

### 3.6 训练规模：`epoch` / `step` 与原版 RVC 的关系（试训前必读）

**一句话**：本项目与原版**同构**——**一轮（epoch）= 原版一轮 = 把训练样本完整过一遍；一步（step）= 原版一个
`global_step` = 一次优化器更新（D 更新一次 + G 更新一次）**。`epoch = step / steps_per_epoch`，跨过整数边界即进入
下一轮（同时 G/D 学习率按 epoch 衰减一次，对应原版 ExponentialLR）。

**一轮的步数**：

```
steps_per_epoch = floor( 可训练样本数 / batch_size / grad_accum )      # 尾部不足一组丢弃
```

- **可训练样本数** = 缓存里满足 `segment_frames ≤ 样本帧数 ≤ bucket` 的样本；其余计入启动日志的 `skipped`。
  默认 `bucket=384` 覆盖全部 3.7s 切片（`skipped=0`）。
- **怎么看**：训练**启动时**控制台会打印一行（同时写入 `train.log`），可直接读取：
  ```
  [trainer] 启动：bucket=384 batch=1 samples=92 skipped=0 steps/epoch=92 epochs=20
            max_steps=0 seed=1234（预计总优化步≈1840）
  ```

**与原版的两点差别（决定你测试时填多大）**：

1. **batch_size**：原版 `config.json` 默认 **4**，本项目默认 **1**。原版一步吃 4 个样本、本项目一步吃 1 个。
   若要"一步等效原版一步（数据量）"，用 `--batch 4`（受 Vulkan 单缓冲/存储范围硬限，常见 4096 MiB；B≥2 常不够）或
   **`--grad-accum 4`**（累积 4 个 micro-batch 再更新一次，显存友好、梯度等价近似）。
2. **样本数口径相同**：原版样本数 = `0_gt_wavs` 的切片数；本项目样本数 = 缓存样本数（**同一套切片**，
   数量基本相同）。因此 `steps_per_epoch` 在相同 batch 下与原版一致。

**对照示例**：原版 `batch_size=4`、切片 N=1000 ⇒ 原版 `steps/epoch=250`；本项目 `--batch 4` 同样 `250`
（一轮对一轮）；若本项目用默认 `--batch 1` 则 `steps/epoch=1000`（小步快跑、显存更省，但每步数据量是原版的 1/4）。

**`--steps N`**：只跑 N 个优化步（跨 epoch 计数），用于冒烟，优先于 `--epochs`。

**规模与硬件的现实约束（实测口径）**：大 `bucket`/`disc_len` 配置的步时与显存开销都明显更高。
train.cpp v0.4.0 起训练缓冲默认优先 device-local，Arc B570 上 10 步 A/B 实测
`B=1/T=384/d=12800` 约 **1.57 秒/步**、`B=2/T=300/d=4800` 约 **2.08 秒/步**
（回退 host-visible 时约 25.6 / 39.4 秒/步）。即便如此，正式长训前仍建议先用小配置试训、
确认稳定后再放大；向导默认值即稳妥档，填大值会收到警告。

**小规模试训建议**：先用 `--bucket 200 --disc-len 1024` 缩小图与判别器输入（更快、更省内存），
`--epochs 1~3` 或 `--steps 5~20`，确认 loss 有限且趋势合理、能存 checkpoint，再放大到正式参数。

## 4. 导出推理 GGUF

训练中 `--export-every N` 会实时导出 `export.ep{N}.gguf`；也可对**任意训练态 GGUF**离线导出：

```powershell
build\bin\rvc-train.exe --export-gguf work\train_myvoice\train.ep5.snapshot.gguf `
    --out work\train_myvoice\myvoice.export.gguf
```

导出内容：折叠 `weight_norm`（`w = g·v/‖v‖`）、Conv1d 权重展平（`dec.ups.*` 除外）、只导推理子集
（`enc_p / flow / dec / emb_g`）、写 `rvc.*` 元数据；产物可被 **RVC-GGML 直接加载**。

## 5. 推理（RVC-GGML）

用导出模型做一次转换：

```powershell
build\bin\RVC-GGML.exe `
    --input <输入wav> `
    --model work\train_myvoice\myvoice.export.gguf `
    --model-dir models `
    --output work\train_myvoice\out.wav `
    --rms-mix-rate 0.75 --pitch 0 --device 0
# 启用检索（有索引时）：
#   --index work\index_myvoice\myvoice.index.gguf --index-rate 0.75
```

- `--model-dir`：hubert/rmvpe 模型所在目录（默认 `models`）。
- `--device 0` = Vulkan，`--device 99` = CPU（下标以 `--list-devices`/启动打印为准）。
- 也可双击 `RVC-GGML.exe`（无参数）进入它自己的中文交互式向导。

## 6. 完整示例（从你的音频到推理）

以下用通用路径演示完整闭环（`<wav目录>` = 你的原始音频，`models` = hubert/rmvpe 所在目录）：

```powershell
# 0) （可选）长训环境变量
$env:TRC_VK_CHUNK_NODES="64"

# 1) 预处理（v1-40k；v2 换 --sr 48000 --version v2）
build\bin\rvc-prep.exe --input D:\myvoice --sr 40000 --version v1 `
    --exp work\cache_myvoice `
    --rmvpe models\rmvpe.gguf --hubert models\hubert.gguf --device 0

# 2) 校验缓存
build\bin\rvc-prep.exe --validate-cache work\cache_myvoice

# 3) 微调 20 epoch，每 5 epoch 存档并导出推理模型（设备下标按 --list-devices 填）
build\bin\rvc-train.exe --train configs\v1-40k-f0.json `
    --exp work\cache_myvoice `
    --weights work\models\f0G40k.train.gguf --d-weights work\models\f0D40k.train.gguf `
    --out work\train_myvoice --device 1 `
    --epochs 20 --batch 1 --bucket 384 --disc-len 12800 `
    --save-interval 1 --export-every 5

# 4) 用导出的推理模型转换一段音频
build\bin\RVC-GGML.exe `
    --input D:\some\test.wav `
    --model work\train_myvoice\export.ep20.gguf `
    --model-dir models `
    --output work\train_myvoice\out.wav --rms-mix-rate 0.75 --device 0
```

等效地，**第 1 步和第 3 步都可以直接双击对应 exe 走中文向导**（§0.6）。

## 7. 配置字段速查（自有 schema）

顶层三段 + 可选 `run`。以 `configs/v1-40k-f0.json` 为例：

| 段 | 关键字段 | 说明 |
|---|---|---|
| `train` | `batch_size/epochs/learning_rate/betas/eps/weight_decay/lr_decay/c_mel/c_kl` | 优化与损失（AdamW + ExponentialLR） |
| `train` | `bucket/disc_len/segment_size/save_interval/seed/grad_accum/log_interval` | 数据/训练控制 |
| `data` | `sampling_rate/filter_length/hop_length/win_length/n_mel_channels/mel_fmin/mel_fmax` | 音频与谱（须与缓存一致） |
| `model` | `version/has_f0/inter_channels/hidden_channels/.../upsample_rates/d_periods` | 模型结构（从零训练据此生成；微调须与权重匹配） |
| `run`（可选） | `exp/out/pretrain_g/pretrain_d/device/resume/export_every/snapshot_keep/scratch/export_run_json` | 运行接线；CLI 覆盖优先 |

- **不实现** `init_lr_ratio/warmup_epochs`（配置里保留但忽略），`fp16_run` 忽略（固定 F32 训练）。
- 更换 `train/data/model` 中影响训练轨迹的字段会导致续训被拒（见 §3.4）。

## 8. 常见问题（FAQ）

- **训练能不能用 CPU？** 不能作为训练目标。CPU 后端很慢且仅调试用；正式训练选 Vulkan GPU。
- **训练速度慢/占的是共享内存？** train.cpp v0.4.0 起默认优先 device-local：独显会用真显存
  （不可映射时经共享 staging），核显/ReBAR 用可映射 device-local；仍可用
  `TRC_VK_HOST_MEMORY=1` 回退旧的 host-visible 行为。提速优先调小
  `bucket`/`disc_len`/`batch`，或提高有效 batch 用 `--grad-accum`。
- **`VK_ERROR_DEVICE_LOST`（独显长训）？** 设 `TRC_VK_CHUNK_NODES=64`（分批提交）；仍复现则记录
  机型/驱动与 `TRC_VK_CHECK=1` 输出反馈。
- **`batch>1` 失败/超限？** Vulkan 单缓冲/存储范围硬限（常见 4096 MiB，实际值见启动日志）；
  用 `--grad-accum` 提升有效 batch，或减小
  `bucket`/`disc_len`。
- **续训报"缺 meta / 配置不一致"？** 见 §3.4；无 `.meta.json` 的旧 checkpoint 不可续训。
- **缓存与配置不一致（`缓存 spec.hop/target_sr/n_fft 不一致`）？** `--sr/--version` 必须与生成缓存时一致。
- **报 `模型与训练缓存不匹配：G 权重为 v1（特征维 256），但缓存特征维为 768…`？** = 模型版本与缓存版本
  不匹配。对齐方式：**v1** 用 f0G40k/f0D40k + v1 缓存 + `configs\v1-40k-f0.json`；**v2** 用 f0G48k/f0D48k +
  v2 缓存 + `configs\v2-48k-f0.json`。G/D 也必须同为 v1 或同为 v2。
- **找不到 hubert/rmvpe（推理）？** 用 `--model-dir` 指向包含 `hubert.gguf`/`rmvpe.gguf` 的目录（默认 `models`）。
- **怎么验证安装/环境？** `rvc-prep --list-devices`、`rvc-train --list-devices`、`rvc-train --selftest`、
  `rvc-prep --selftest`；或直接双击任一 exe 进入向导。
- **控制台中文乱码？** 程序启动时会自动把控制台切到 UTF-8。若仍乱码（个别旧版 PowerShell 5.1），
  先执行 `chcp 65001`；用 Windows Terminal / PowerShell 7 更省事。
- **诊断/自检开关（非日常）**：`rvc-train --selftest-forward/-backward/-loss/-train-step/-train-loop/-data`、
  `--selftest-trainer/-grad-accum/-resume/-wizard/-scratch`；脚本对拍见 `tools\README.md`。
