# RVC-GGML 使用文档：发布版使用与原版对比（v0.2.0）

> 本文以 **RVC-GGML v0.2.0 Windows 发布版**为准，说明从模型转换到应用调用的完整用法，
> 并对照原版 RVC（WebUI/CLI）逐项解释参数、报错与系统要求。

---

## 一、系统要求（运行端）

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11 64 位 | 发布版仅提供 win64 构建 |
| CPU | x86-64 且支持 **AVX2** | 发布版按 AVX2 指令集编译；2013 年后 Intel / 2015 年后 AMD 基本都支持 |
| 内存 | 建议 8 GB 以上 | 换算依赖主机内存与显存 |
| GPU（可选） | 支持 **Vulkan 1.2** 的显卡与驱动（需 16-bit storage，绝大多数 2017 年后的驱动都满足） | Intel 核显/独显、AMD、NVIDIA 均可；无需 CUDA |
| 显存 | 建议 4 GB 以上 | 5 秒音频约占用「权重 ~450 MB（fp16）+ 图缓冲 ~0.4 GB」；长音频更大 |
| 磁盘 | 运行包约 1.7 GB（含全档位模型）；输出另计 | 只带少量模型可更小 |
| 其他 | 系统自带 `vulkan-1.dll`（驱动提供）；包内自带 `vcomp140.dll`（OpenMP 运行库） | 不需要安装 Python、CUDA、VC++ 运行库 |

**CPU 模式**：`--device 99`。CPU 无 AVX2 的老机器不在支持范围内。

## 二、发布包结构

```
RVC-GGML-v0.2.0-win64\
├─ RVC-GGML.exe            主程序
├─ vcomp140.dll            OpenMP 运行库（必须与 exe 同目录）
├─ README.md               快速说明
├─ 交互模式.bat            双击进入交互向导
├─ 查看可用设备.bat        列出 Vulkan 设备
├─ 示例转换.bat            一条示例命令
├─ input\                  输入音频样例（wav）
├─ output\                 输出目录（转换结果/量化测试结果）
├─ models\                 模型（见下表）
└─ scripts\                模型转换与校验脚本（Python）
```

`models\` 内容（每类均提供 5 档：fp16 / q8_0 / q5_1 / q4_1 / q4_0）：

| 文件 | 用途 | fp16 体积 | 各档位体积参考 |
|---|---|---|---|
| `hubert.gguf` (+`.q*.gguf`) | 内容特征（必需） | 190.5 MB | 110.5 / 83.8 / 73.1 / 67.8 MB |
| `rmvpe.gguf` (+`.q*.gguf`) | 音高提取（f0 模型必需） | 178.9 MB | 100.9 / 74.9 / 64.5 / 59.3 MB |
| `guanguanV1.gguf` (+`.q*.gguf`) | 角色模型（v1 / 40 kHz / f0） | 70.2 MB | 54.0 / 48.7 / 46.5 / 45.4 MB |
| `youzhanv2-xi.gguf` (+`.q*.gguf`) | 角色模型（v2 / 48 kHz / f0） | 75.1 MB | 58.9 / 53.5 / 51.4 / 50.3 MB |
| `guanguanV1.index.gguf` | 检索索引（可选，配合 `--index-rate`） | 33.2 MB | 索引不量化 |

> 量化档位的含义：q8_0 ≈ 接近无损；q5_1/q4_1 为折中；q4_0 体积最小、音质差异相对可闻（见"已知限制"）。

## 三、快速开始

### 3.1 交互模式（推荐）

双击 `交互模式.bat`，或在命令行运行 `RVC-GGML.exe`。向导依次询问：

1. **角色模型**：列出 `models\` 下所有角色模型（自动读取版本/采样率/f0/说话人数/量化档位）；
2. **量化档位**：列出可用的统一档位（fp16/q8_0/…），对 hubert+rmvpe+角色模型一并生效；
3. **输入音频**：列出 `input\*.wav`，也可输入任意路径；
4. **设备**：列出 Vulkan 设备与 CPU（默认优先 GPU 0）；
5. **转换参数**：变调、说话人（多人模型才问）、索引混合率（存在同名索引才问）、RMS 混合率、清音保护、可选重采样；
6. 确认后开始转换，输出为 `output\<输入名>_<模型名>[_<档位>].wav`，结束后按 Enter 退出。

### 3.2 命令行模式

```powershell
# 基础转换（fp16，GPU 0）
RVC-GGML.exe --input input\test_5s_16k.wav --model models\guanguanV1.gguf ^
    --output output\demo.wav --rms-mix-rate 0.75 --device 0

# 一键切换整套模型的量化档位
RVC-GGML.exe --input input\test_5s_16k.wav --model-dir models --quant q4_0 ^
    --output output\demo_q4_0.wav --rms-mix-rate 0.75 --device 0

# 带检索（需要同名/指定索引）
RVC-GGML.exe --input input\test_5s_16k.wav --model models\guanguanV1.gguf ^
    --index models\guanguanV1.index.gguf --index-rate 0.75 ^
    --output output\demo_idx.wav --device 0

# 查看设备
RVC-GGML.exe --list-devices
```

## 四、命令行参数速查（与原版对照）

| 参数 | 取值/默认 | 含义 | 对应原版 RVC 概念 |
|---|---|---|---|
| `--input <wav>` | 必填（转换模式） | 输入音频；任意采样率/声道，自动转 16k 单声道 | WebUI 的"待转换音频" |
| `--output <wav>` | `output/converted.wav` | 输出 16-bit PCM 单声道 WAV | 输出文件 |
| `--model <gguf>` | `models/guanguanV1.gguf` | 角色模型 | WebUI 选择 .pth |
| `--model-dir <dir>` | `models` | 模型目录（hubert/rmvpe/索引所在处） | — |
| `--quant <level>` | 空=按文件实际档位 | `fp16/q8_0/q5_1/q4_1/q4_0`，统一替换 hubert/rmvpe/角色模型 | 原版无（本项目量化功能） |
| `--pitch <n>` | `0` | 变调半音数：`+12` 升八度、`-12` 降八度 | 变调（整数） |
| `--sid <n>` | `0` | 说话人 ID（多人模型） | 说话人 ID |
| `--index <gguf>` | 不用 | 检索索引（本项目为 `.index.gguf`） | `*.index` 检索文件 |
| `--index-rate <r>` | `0` | 检索特征混合率 0~1；常用 0.5~0.75 | 检索特征占比 |
| `--protect <p>` | `0.33` | 清音保护 0~0.5：越大越保留原清音特征 | 保护清辅音 |
| `--rms-mix-rate <r>` | `1.0` | 响度混合 0~1：1=完全用转换结果响度，0=完全用原音频响度 | 响度因子（rms_mix_rate） |
| `--resample-sr <n>` | `0` | 输出重采样率；0=模型采样率（40k/48k） | 输出采样率（音频变调采样） |
| `--device <id>` | `99` | `0+`=Vulkan 设备编号，`99`=CPU | 原版为"选择 GPU/推理设备" |
| `--x-pad` / `--x-query` / `--x-center` / `--x-max` | `1/6/38/41`（秒） | 长音频切块参数：前后补齐、切点搜索半径、切块间隔、启用切块的时长阈值 | `configs/config.py` 的 device_config |
| `--list-devices` | — | 列出可用 Vulkan 设备 | — |
| `--interactive, -i` | — | 强制进入交互向导 | — |
| `--noise-dir <dir>` / `--f0-inject` | — | **仅验证用**：注入参考噪声/f0，使 C++ 与 Python 可逐样本对比 | 无 |
| `--audio-selftest` / `--hubert-selftest` / `--rmvpe-selftest` / `--vits-selftest` | — | 开发自检模式（需要参考数据/模型） | 无 |

**固定/不提供的原版参数**：

- f0 算法固定为 **RMVPE**（原版可选 pm/harvest/crepe）；`filter_radius` 固定 3（RMVPE 不使用）；
- 不提供 UVR5 人声分离、训练/微调、实时变声、TTS；
- 自定义 f0 曲线、harvest 参数等高级项不支持。

## 五、模型转换（.pth / .pt / .index → GGUF）

运行端不能直接读原版模型，需要用 `scripts\export_gguf.py` 转换。

### 5.1 转换环境

| 组件 | 要求 | 用途 |
|---|---|---|
| Python | 3.9 ~ 3.13（实测 3.9.13 / 3.13） | 运行脚本 |
| PyTorch（CPU 版即可） | 1.x/2.x（实测 2.0.0+cpu / 2.12.1+cpu） | 读取 .pt/.pth |
| numpy | 1.21+ | 数值处理 |
| `gguf`（pip 包） | 实测 0.16.2 | 写 GGUF |
| `faiss-cpu` | 仅转换 `.index` 需要 | 读取 FAISS 索引 |
| `librosa`（可选） | 用于 RMVPE mel 滤波器组；缺失时脚本用内置等价实现 | — |

安装（清华源示例）：

```powershell
pip install numpy torch gguf -i https://pypi.tuna.tsinghua.edu.cn/simple
pip install faiss-cpu -i https://pypi.tuna.tsinghua.edu.cn/simple   # 只有转索引才需要
```

### 5.2 转换命令

在项目/发布包根目录执行（**注意当前目录**：脚本在 `scripts\` 下，输入输出相对当前目录解析）：

```powershell
python scripts\export_gguf.py hubert --input <hubert_base.pt> --out models\hubert.gguf --dtype fp16
python scripts\export_gguf.py rmvpe  --input <rmvpe.pt>       --out models\rmvpe.gguf  --dtype q8_0
python scripts\export_gguf.py model  --input <角色.pth>        --out models\<角色>.gguf --dtype q4_0
python scripts\export_gguf.py index  --input <角色.index>      --out models\<角色>.index.gguf
# 从 RVC 根目录批量（hubert 固定 fp16；角色模型逐个按 --dtype；自动转 logs/*.index）
python scripts\export_gguf.py all --rvc-root <RVC原版仓库根目录> --out models --dtype fp16
```

`--dtype` 可选：`f32 / fp16 / q8_0 / q5_0 / q5_1 / q4_0 / q4_1`。

**命名约定（`--quant` 依赖）**：

- fp16 基准：`hubert.gguf`、`rmvpe.gguf`、`<角色>.gguf`
- 量化档位：`hubert.q4_0.gguf`、`rmvpe.q4_0.gguf`、`<角色>.q4_0.gguf`
- 索引：`<角色>.index.gguf`（不区分档位）

转换成功的标志：打印 `量化 x / F16 y / F32 z，文件 xxx MB`。

### 5.3 转换端常见报错

| 现象 | 原因 | 处理 |
|---|---|---|
| `can't open file '...\export_gguf.py'` | 脚本路径不对（不在当前目录） | 用 `python scripts\export_gguf.py ...`，并确认在发布包根目录执行 |
| `FileNotFoundError: models\xxx.pth` | 输入路径相对当前目录不存在 | 用完整路径或先 `cd` 到放 .pth 的目录 |
| `缺少 gguf 包` | 未安装 gguf | `pip install gguf` |
| `RVC 模型缺少 'weight' 字段` | 输入不是 RVC 角色模型 .pth | 确认文件来源与格式 |
| `仅支持 IndexIVFFlat（当前 …）` | 索引不是 FAISS IVF Flat | 原版 RVC 索引一般满足；其他类型暂不支持 |
| `[WARN] xxx: 量化失败…回退 F16` | 该张量不满足量化条件 | 正常警告，不影响使用 |
| 转换很慢 | 读 .pt + 逐张量量化 | 50s 模型约 1 分钟；耐心等待 |

## 六、运行端报错对照表

| 报错信息 | 含义 | 处理 |
|---|---|---|
| `无法打开 GGUF 文件: <path>` / `gguf_init_from_file: failed ... (No such file or directory)` | 路径不存在的**或路径含中文/非 ASCII**（ggml 按 UTF-8 打开文件，而 Windows 命令行参数是本机编码） | 用 `--list-devices` 前先确认文件在；**模型路径请使用纯英文**；音频路径不受此限 |
| `GGUF 缺少 general.architecture 键` | 不是本工具导出的 GGUF | 用 `scripts\export_gguf.py` 重新转换 |
| `权重缓冲区分配失败（显存不足？）` | 显存/内存不足以放下模型 | 换更低量化档位；关闭其他占显存程序；或 `--device 99` 用内存 |
| `GPU 设备 ID N 越界（可用 M 个），回退 CPU` | `--device` 编号不存在 | 先 `--list-devices`，用实际编号（0 起） |
| `GPU 设备初始化失败，回退 CPU` | Vulkan 驱动/设备异常（驱动过旧、被占用） | 更新显卡驱动；或继续用 CPU |
| `GGML 计算失败: <status>` | 图执行失败（显存不足/驱动异常/不支持算子） | 换低档位/CPU；更新驱动；把完整输出反馈 |
| `量化档位文件不存在: <path>` | `--quant q4_0` 但缺少对应档位文件 | 用 `scripts\export_gguf.py` 生成该档位，或去掉 `--quant` |
| `VITS 缺失权重: <name>` / `RMVPE 缺少张量` | 模型与预期结构不符（旧/坏文件、类型用错） | 用当前脚本重导模型；确认 `--model` 是角色模型而非 hubert/rmvpe |
| `linear: 维度不匹配` | 角色模型与特征维度不符（如把 v2 模型与 v1 数据混用） | 确认模型与流程匹配 |
| `输入音频为空` / 读取失败 | WAV 为空/损坏/非 WAV | 换文件；支持 WAV（PCM 8/16/24/32-bit、32-bit float、A/μ-law） |
| `f0 注入文件缺失` / `噪声文件缺失` | 使用了 `--f0-inject`/`--noise-dir` 但参考数据不全 | 仅验证流程需要；普通使用不要加这两个参数 |
| `找不到模型: models\hubert.gguf`（自检） | 自检模式要求的文件缺失 | 自检前确认 `models\` 与 `output\ref\` 完整 |
| 程序闪退/无输出 | 路径含中文（见第一条）或模型文件损坏 | 用英文路径重试；校验模型大小 |

## 七、常见问题（FAQ）

**Q1：支持哪些输入格式？**
WAV（PCM 8/16/24/32-bit、32-bit float、A/μ-law）；多声道自动下混；任意采样率自动重采样到 16 kHz。

**Q2：输出是什么格式？**
16-bit PCM 单声道 WAV，采样率为模型采样率（40 kHz / 48 kHz），可用 `--resample-sr` 指定（如 44100/48000）。

**Q3：转换结果和原版 RVC 一样吗？**
在同模型、同噪声、同 f0 下，波形相关系数 0.999+（听感一致）。由于浮点实现与量化差异，
不是逐位一致；原版每次推理的随机噪声本身也会造成差异。

**Q4：为什么同一输入两次输出不完全一样？**
本程序默认使用固定随机种子，正常情况下可复现。但 f0 估计在极少数帧（显著性 top1/top2 极接近时）
存在浮点敏感性，可能带来相位级差异（听感影响很小）。

**Q5：变调怎么设？**
`--pitch 12` 升八度，`--pitch -12` 降八度，`--pitch 2` 升两个半音。对应原版 WebUI 的"变调"。

**Q6：`--index-rate` 设多少？**
0.5~0.75 是常用区间（越大越接近训练集音色，但内容可能更"粘"）；0 = 完全不使用检索。

**Q7：`--protect` 和 `--rms-mix-rate`？**
`--protect`（默认 0.33）越大越保留原音频的清音（气声/齿音）特征；
`--rms-mix-rate` 控制响度混合：1=完全采用转换结果响度，0=完全采用原音频响度。

**Q8：显存不足怎么办？**
降低量化档位（如 q4_0）→ 缩小切块（减小 `--x-center`，块长约为 `x_center + 2×x_pad` 秒）→ 用 CPU（`--device 99`）。

**Q9：模型路径可以用中文吗？**
**不可以（当前版本限制）**。GGUF 加载要求 UTF-8 路径，而 Windows 命令行参数为本机编码；
请把模型/目录放在纯英文路径下。音频路径可含中文。

**Q10：原版的 UVR5 人声分离/训练/实时在哪？**
本版本只做离线转换，不含这些功能；输入音频请先用原版或其它工具分离好人声。

**Q11：为什么音高算法不能选？**
本版本固定 RMVPE（精度与速度的折中），没有 pm/harvest/crepe。

**Q12：模型转换会不会损失音质？**
fp16 无感；q8_0 接近无损；q5_1/q4_1 有轻微差异；q4_0 差异相对可闻（尤其音色细节）。
建议用 q8_0 或 q5_1 平衡体积与质量；具体以实测听感为准。

**Q13：长音频（几分钟）和 48 kHz 角色模型能稳定跑吗？**
能（2026-09-17 起的构建）。此前的版本在 Vulkan 上遇到较长切块时会因矩阵乘 workgroup 超限而中断
（48 kHz 模型尤甚）。修复需要**修改 ggml 源码**（Vulkan 矩阵乘 N 维切分），补丁见源码仓库
`patches/ggml-vulkan-matmul-n-split.patch`，技术细节见《技术文档二》§5.5；从源码构建时请务必应用，
直接使用官方 ggml 编译会复现该问题。

## 八、与原版的差异一览（使用视角）

| 维度 | 原版 RVC | RVC-GGML v0.2.0 |
|---|---|---|
| 操作界面 | WebUI（浏览器）+ CLI | 命令行 + 交互向导（无 WebUI） |
| 运行环境 | Python + torch + fairseq… | 单 exe + 驱动 |
| 模型使用 | 直接选 .pth/.pt/.index | 需先转 GGUF（含量化档位） |
| 硬件 | 取决于 PyTorch 后端（CUDA/DML…） | Vulkan 通用（跨厂商） |
| 量化 | 无官方推理量化 | 5 档混合量化，显存/体积可调 |
| 音高算法 | 4 种可选 | 仅 RMVPE |
| 人声分离/训练/实时 | 支持 | 不支持 |
| 长音频 | 自动切块 | 自动切块（参数同原版） |
| 非 ASCII 路径 | 支持 | **模型路径不支持**（音频支持） |

## 九、版本信息

- 版本：RVC-GGML v0.2.0（Windows x64）；2026-09-17 修复构建（长音频/48 kHz 崩溃修复）
- 模型格式：GGUF 布局 v2（`rvc.conv_flat`；旧布局仍可加载，但量化需用本版脚本重导）
- 随机种子：固定（除非注入参考数据）
- **构建说明（重要）**：本程序链接的是**修改过的本地 ggml 源码**——Vulkan 后端矩阵乘新增
  N 维切分，修复 48 kHz 角色模型与超长音频（单块 > 43.7 s）在 Vulkan 上的崩溃断言
  （`maxComputeWorkGroupCount`）。补丁在源码仓库 `patches/ggml-vulkan-matmul-n-split.patch`；
  从源码构建时必须应用该补丁，否则问题复现。详见《技术文档二》§5.5。
- 文档配套：《技术文档一：项目移植与实现概览》《技术文档二：ggml/Vulkan 实现细节》
