# RVC-GGML 源码结构与模块手册

> 面向二次开发/代码维护。与《技术文档三》的分工：文档三讲"算法怎么算"（脱离源码），
> 本手册讲"代码怎么组织"——目录与文件职责、关键类与接口、对象生命周期、调用链与数据流。
> 复杂子算法（flow/生成器、GRU 状态接力、重采样器等）此处只给主干与入口，
> 需要逐行拆解时可另出专项文档（见 §十一）。

## 一、仓库结构与构建

### 1.1 目录总览

| 路径 | 内容 | 作用 |
|---|---|---|
| `CMakeLists.txt` | 构建脚本 | 解析 ggml 依赖、生成 `rvc_core` 静态库与 `RVC-GGML.exe`、检测 ggml 补丁 |
| `README.md`（仓库根） | 项目说明 | 总览、构建与快速上手 |
| `docs/` | 文档一/二/三/四 | 概览、ggml 细节、算法统一说明、本源码手册 |
| `patches/` | ggml 补丁与说明 | Vulkan matmul N 维切分；升级 ggml 后必须重新应用 |
| `include/` | `dr_wav.h`、`pocketfft_hdronly.h` | 第三方单头库（WAV 读写、实数 FFT），不改动 |
| `src/` | 全部 C++ 实现 | 见 §三~§七 |
| `scripts/` | Python 工具链 | 模型转换（export）、数值校验（verify） |
| `models/` | GGUF 模型 | 用户生成的 `hubert.gguf`、`rmvpe.gguf`、`<角色>.gguf`、`<角色>.index.gguf` 及各量化档位 |
| `build/` | CMake 构建树 | 含 `RVC-GGML.exe` 与 ggml 各子工程 |

### 1.2 CMakeLists.txt

1. **ggml 依赖解析（优先级）**：`RVC_GGML_DIR`（缓存变量）→ `find_package(ggml)` →
   兄弟目录 `../ggml-master` → `../ggml` → FetchContent 拉官方 v0.23.0；
2. **补丁**：若启用 Vulkan，官方 ggml 缺少 N 维切分补丁，FetchContent 路径下构建系统会
   自动应用 `patches/ggml-vulkan-matmul-n-split.patch`（幂等，源码已含补丁则跳过）；
   本地 ggml 源码路径则只做检测——读取 `src/ggml-vulkan/ggml-vulkan.cpp` 查找标记
   `ggml_vk_mul_mat_q_f16_m_split`，缺失即 `message(WARNING)`（长音频/48kHz 模型会在运行期断言，
   需手动应用补丁）；
3. **目标**：`rvc_core`（静态库，全部推理代码）+ `RVC-GGML`（`main.cpp`，链接 `rvc_core`）；
   MSVC 下统一 `/utf-8` 与静态 CRT。

### 1.3 分层调用关系

```
main.cpp
 ├─ engine        (GgmlDevice / GgmlGraphRunner)
 ├─ gguf_model    (元数据 + 权重上传)
 ├─ rvc/pipeline  (全链路编排)
 │   ├─ hubert/     HubertEncoder
 │   ├─ rmvpe/      RmvpeExtractor
 │   ├─ vits/       Synthesizer ── text_encoder / flow / generator
 │   ├─ rvc/retrieval  RetrievalIndex
 │   └─ rvc/sinegen    SineGen
 ├─ audio/        (WAV、重采样、DSP、mel)
 └─ vits/modules  (被 hubert/rmvpe/vits 三个图构建器共用的算子库)
```

## 二、公共基础设施

### 2.1 `src/utils.{h,cpp}`

- `Timer`：毫秒计时与格式化（日志打印耗时）；
- `Logger`：`INFO/WARN/ERROR` 三级，输出到 stderr；`progress()` 简易进度条；
- `utils::` 文件与字符串工具：`file_exists`、`list_files(dir, ext)`、`stem`、`filename`、
  `ensure_directory`、`trim/split`。被 CLI 向导与各模型加载路径使用。

### 2.2 `src/engine.{h,cpp}`

**`GgmlDevice`**（RAII 持有 `ggml_backend_t`）：
- `device_id >= 0`：枚举 `GGML_BACKEND_DEVICE_TYPE_GPU/IGPU` 设备，取第 N 个初始化；
  初始化失败或越界时打印告警并回退 CPU；
- `device_id == 99`：直接初始化 CPU 后端；
- `name()` 供日志与交互界面显示。

**`GgmlGraphRunner`**（所有静态图的执行容器）：
- 构造参数：`ctx_mem_size`（张量元数据池）、`max_nodes`（图节点上限）；
- 生命周期：`ctx()` 建图 → `expand(node)` 记录输出 → `allocate()` 分配 → `compute()` →
  `set_input/get_output` 读写；
- 关键实现：`allocate()` = `ggml_gallocr_new(default_buffer_type)` +
  `reserve` + `alloc_graph`；记录 `buffer_size()`/`node_count()` 供日志与显存排查；
- 输入输出：`ggml_backend_tensor_set/get`，必须与张量字节数完全一致（有断言检查）。

```
runner = GgmlGraphRunner(backend, ctx_MB, max_nodes)
build_graph(runner.ctx(), ...)            # 各模型模块负责
for out in outputs: runner.expand(out)
runner.allocate()
repeat: set_input(...); runner.compute(); get_output(...)
```

### 2.3 `src/gguf/gguf_model.{h,cpp}`

**接口**：

| 成员 | 说明 |
|---|---|
| `load(path, backend)` | 解析元数据 + 全部权重上传到后端 |
| `load_meta_only(path)` | 只读元数据（交互向导扫描模型，不占显存） |
| `weight(name)` / `has_weight` | 取张量指针（按名字精确匹配） |
| `meta_u32/f32/bool/str/array_str/array_i32` | 元数据访问（带 fallback） |
| `read_f32(name)` | 把权重拷回主机并转 F32（支持 F32/F16；量化张量不支持） |
| `tensor_count()` | 统计 |

**权重上传流程**（`load_weights`）：

```
buffer = ggml_backend_alloc_ctx_tensors_from_buft(ctx_weights, default_buft(backend))
file   = _wfopen(path)                          # 宽字符路径，支持非 ASCII 文件系统路径
for t in ctx_weights:
    tid = gguf_find_tensor(name)
    offset = data_offset + tensor_offset(tid)
    读精确字节数 → ggml_backend_tensor_set(t, buf, 0, ggml_nbytes(t))
```

说明：张量数据不经转换直传（GGUF 的量化块布局与 ggml 内存布局一致）；加载期即完成
F32/F16 区分，量化反量化发生在计算时。`read_f32` 用于主机侧需要数值的少量权重
（如 RMVPE mel 滤波器组、SineGen 的 `l_linear`、相对位置嵌入）。

## 三、音频与 DSP（主机侧）

### 3.1 `src/audio/audio_io.{h,cpp}`

- `AudioData`：`samples`（交错 float）、`sample_rate`、`num_channels`、`total_samples`；
- `load_wav`：dr_wav 读取任意 PCM/float 格式，统一转 float 交错；
- `save_wav` / `save_wav_i16`：写 16-bit PCM；管线用后者直接落盘已量化的 int16；
- 重采样核心 `windowed_sinc_resample`：Kaiser 窗（beta≈7.865）加窗 sinc，多相结构，
  截止频率 `0.95*min(src,dst)`；`resample_mono` 为单声道包装；
- `to_mono_16k`：先按声道求均值下混，再重采样到 16k。

调用位置：`main::run_convert` 读输入、pipeline 可选输出重采样、`--audio-selftest`。

### 3.2 `src/audio/dsp.{h,cpp}`

| 函数 | 实现要点 | 被谁调用 |
|---|---|---|
| `high_pass_48hz_in_place` | 5 阶 Butterworth 系数 + `lfilter_zi` 初始状态 + 奇扩展边界，前向/反向各滤一次（filtfilt）；与 scipy 逐位一致 | pipeline §1、audio-selftest |
| `reflect_pad` | numpy `mode='reflect'` 语义（不含端点重复） | 切块曲线、管线补齐、RMS |
| `frame_rms` | 窗长 `sr/2*2`、hop `sr/2`、中心对齐、边界反射（对齐 librosa） | RMS 混合 |
| `interpolate_linear` | 线性插值到目标帧数（对齐 `F.interpolate(mode='linear', align_corners=True)`） | RMS 混合 |
| `apply_rms_mix` | `out *= rms_src^(1-r) * rms_out^(r-1)` | pipeline §6 |
| `audio_sum_curve` | 160 点滑动 `|x|` 绝对和（曲线用于切点搜索） | 自检、切块 |
| `quiet_split_points` | `t_center` 间隔搜索 ±`t_query` 内曲线最小点 | **自检对照用**；管线主循环内联同语义实现 |
| `coarse_pitch_bin` | `1 + round(12*log2(f0/50))`，范围 1..255，清音 0 | pipeline（全段与逐块） |
| `median_filter_f0` / `interpolate_unvoiced` | f0 中值滤波 / 清音插值 | 目前为保留工具，主管线未调用 |

### 3.3 `src/audio/mel.{h,cpp}`

- `make_mel_filterbank`：librosa HTK 风格三角滤波器组（仅参考/自检需要，管线直接用 GGUF 表）；
- `log_mel_spectrogram`：pocketfft 实数 FFT（Hann 窗、center 模式）→ 功率谱 → 滤波器组 →
  log → clamp；输出 `[n_mels, frames]` 行主序。RMVPE 唯一使用方。

## 四、算子封装层 `src/vits/modules.{h,cpp}`

定位：**函数式算子库**（输入 `ggml_context*` 与张量，返回新张量），不管理图生命周期；
被 HuBERT / RMVPE / VITS 三个图构建器共用。所有算子输出 F32（量化权重由 `mul_mat` 内部反量化）。

| 分组 | 接口 | 要点 |
|---|---|---|
| 上下文 | `GraphContext`（ctx+graph 容器） | 轻量封装；三个模型构建器实际使用 `GgmlGraphRunner` |
| 基础 | `linear` | `mul_mat(W,x)` + bias 广播；`W=[K,N]` |
| 卷积 | `conv1d`（`flat` 开关） | flat：`im2col + mul_mat`（量化友好）；非 flat：`ggml_conv_1d` |
| | `conv1d_grouped` | 逐组 `view+cont+conv2d`（H=1）后 `concat` |
| | `conv1d_ct` / `conv1x1_ct` | `[C,T]` 布局包装（内部转置到 `[T,C]`） |
| 归一化 | `layer_norm` / `group_norm` | 沿 `ne0` / 通道维 `ne2` |
| 索引 | `get_rows` | pitch 嵌入、说话人嵌入查表（F32 表） |
| 相对位置 | `relative_to_absolute` / `absolute_to_relative` | enc_p 相对 logits ↔ 注意力权重形状变换 |
| 辅助 | `sliding_window` | `unfold` 语义（未在主管线使用） |
| | `make_const_f32` | 登记常量输入（分配后一次性写入） |
| | `to_f32` / `permute_cont` / `slice_channels` | 类型提升、置换+连续化、`[C,T]` 通道切片 |
| | `mul_checked` / `add_checked` / `check_dim*` | 广播/维度校验，构建期尽早报错 |

**flat 卷积的实现要点**（`conv1d` 内部）：kernel 参数张量只提供形状（im2col 不读数据）；
列向量类型 = 权重 F16→F16，其余→F32；输出 `[O, OW*B]` 经 `permute_cont` 转回 `[OW, O, B]`。
这与文档三 §4.2 的伪代码一一对应。

## 五、模型模块

### 5.1 HuBERT `src/hubert/hubert.{h,cpp}`

**职责**：16k 波形 → 内容特征（v1 256 维 / v2 768 维，50 fps）。

| 组件 | 说明 |
|---|---|
| `Config` / `read_config` | 卷积通道/核/步长、hidden、heads、pos_conv 组数、`conv_flat` |
| `feature_extractor` | 7 层 Conv1d+GELU；第 0 层附加逐通道 GroupNorm（reshape `[T,1,C,1]` 后 groups=C） |
| `encoder_layer` | Post-Norm Transformer：逐头 `mul_mat` 注意力（q/k/v 头切片→`cont`）、残差、LayerNorm、FFN（GELU erf） |
| `build_graph` | 卷积前端 → LayerNorm → `post_extract_proj` → `pos_conv`（pad + 分组卷积 + GELU + 裁长）→ `encoder.layer_norm` → 12 层；输出 `layer9`（索引 8，v1）、`layer12`、`final_proj` |
| `HubertEncoder` | 复用入口：按输入样本数缓存图；`extract(audio, v2)` 上传波形、执行、取输出 |

```
HubertEncoder.extract(audio, v2):
    if built_samples != audio.size():        # 形状变了才重建
        build(samples)                       # 建图 + 分配 + 缓存输入/输出张量
    runner.set_input(in, audio); runner.compute()
    return get_output(v2 ? out_l12 : out_proj)
```

调试：`RVC_HUBERT_DUMP=1` 时 `debug_tensors()` 收集中间张量名与指针，自检程序将其
`set_output + expand` 后落盘（`cpp_dbg_*.raw`），供逐阶段数值对照。

### 5.2 RMVPE `src/rmvpe/rmvpe.{h,cpp}`

**职责**：整段 16k 波形 → f0（Hz）。四张静态子图 + 主机侧窗口/分块调度。

| 子图 | 构建函数 | 输入/输出 |
|---|---|---|
| feature（DeepUnet） | `build_feature_graph` | mel `[128, T]` → 特征 `[384, T]` |
| GRU 前向 | `build_gru_graph(reverse=false)` | `[384, 512]` + keep + h0 → 序列 `[256,512]` + 末隐状态 |
| GRU 反向 | `build_gru_graph(reverse=true)` | 同上（块内逆序展开） |
| head | `build_head_graph` | `[fwd;rev]` → 显著性 `[360,512]` |

**`RmvpeExtractor::Impl` 状态**：四个 `GgmlGraphRunner`、各自的常驻输入/输出张量、
`feature_frames` 缓存、mel 滤波器组（主机）。

**`infer()` 主流程**（主干）：

```
mel = compute_mel(audio)                       # pocketfft 前端
padded = 32 * ceil(frames/32)                  # 时间维 pad
single_shot = padded <= kFeatureSingleShotLimit
ensure_feature_graph(single_shot ? padded : 8192)     # 形状变化才重建
for 每个窗口（整段或 4096 有效 + 2×2048 上下文）:
    copy_mel_window(...); feature.compute(); 取有效区到 features
for 每个 512 帧块（前向）: fill_gru_chunk → fwd.compute → 保存序列 + 末状态接力
for 每个 512 帧块（反向，从尾部向前）: rev.compute → head.compute → 写显著性
f0 = decode_salience(salience, frames, threshold)     # argmax + 邻域加权 + 阈值
```

**关键常量**（同文件顶部）：`kFeatureActiveFrames=4096`、`kFeatureOverlapFrames=2048`、
`kFeatureSingleShotLimit=16352`（Vulkan 安全上限，推导见文档三 §6.2）、`kGruChunkFrames=512`。

**辅助函数**：`copy_mel_window`（窗口对齐/补零）、`copy_feature_rows`（只取有效行）、
`fill_gru_chunk`（帧数不足 512 时补零 + keep 掩码）、`decode_salience`。

### 5.3 VITS `src/vits/*`

**配置**：`synthesizer.h::Config`，由 `read_config` 从 GGUF 元数据读取；`hop_samples =
prod(upsample_rates)`；`flow_n_layers` 从权重名探测。

**子模块与构建函数**：

| 文件 | 函数 | 职责 |
|---|---|---|
| `text_encoder.cpp` | `expand_relative_embedding` | 把 `[2W+1, D]` 嵌入窗口展开为 `[2T-1, D]` 或转置 `[D, 2T-1]` 常量 |
| | `attention_layer` | 每层：q/k/v（1×1 conv）→ 逐头 score + 相对 logits → softmax → 上下文 + 相对 value 项 → 输出投影 |
| | `ffn_layer` | k=3 same padding + ReLU 的两层卷积 |
| | `build_text_encoder_stats` | 特征投影 + pitch 查表 + `√H` 缩放 + LeakyReLU → 6 层 → proj → `[2*inter, T]` |
| `flow.cpp` | `build_wn` | WaveNet 残差块：`cond_layer` 一次算出所有层的条件，按层切片 `repeat`；`in_layers` + 双门（tanh*sigmoid）+ `res_skip_layers` 分流 |
| | `coupling_reverse` | mean-only 逆仿射：`x1 -= post(WN(pre(x0), g))` |
| | `build_flow_reverse` | 顺序 `{6,4,2,0}`：每步先 `mul_mat(flip_matrix, z)` 翻转通道，再做耦合逆 |
| `generator.cpp` | `conv_transpose1d_pytorch` | `ggml_conv_transpose_1d(p0=0)` 后两侧裁 `(k-s)/2` |
| | `resblock1` | 3 组（膨胀 1/3/5）：`convs1` 带膨胀 + `convs2` 核 3，残差相加 |
| | `build_generator` | `conv_pre` → 条件项 → 4×[LeakyReLU + 上采样 + 噪声卷积 + 3×残差块取均值] → LeakyReLU(0.01) → `conv_post` → tanh |

噪声卷积规则（`build_generator` 内）：`stride = 其余上采样率之积`；核长 `stride==1 ? 1 : 2*stride`。

**`synthesizer.cpp` 编排**：

```
Synthesizer.build(frames, feature_dim, sid):
    runner = GgmlGraphRunner(1024MB, 65536)
    in_features [feature_dim, frames]、in_noise [inter, frames]
    (f0) in_pitch [frames] I32、in_source [frames*hop]
    sid 常量张量 → get_rows(emb_g) → g
    flip 常量（192×192 反对角置 1）
    stats = build_text_encoder_stats(...)      # 相对位置常量在构建期登记
    m/logs 切分；z_p = m + exp(logs)*noise*0.66666
    z = build_flow_reverse(...); audio = build_generator(...)
    五个输出 set_output + expand + allocate
    常量与 sid 只写一次
Synthesizer.infer(input):
    (frames/feature_dim/sid 变化则重建)
    上传 features/pitch/noise/source → compute → 取 audio 与 m/logs/z_p/z（验证字段）
```

布局：enc_p/flow 全程 `[C,T]`（`conv1d_ct` 包装）；生成器内部 `[T,C]`；入口/出口各一次
`permute_cont`（见 `generator.cpp` 首行）。

## 六、全链路与检索

### 6.1 `src/rvc/pipeline.{h,cpp}`

**职责**：把上述组件串成与 Python `pipeline.py` 等价的一次转换。

| 结构 | 说明 |
|---|---|
| `PipelineConfig` | `x_pad/x_query/x_center/x_max`（秒） |
| `ConvertOptions` | 变调、sid、index_rate、protect、rms_mix_rate、resample_sr、可选索引指针、验证模式（`noise_dir`/`f0_inject`） |
| `RvcPipeline::Impl` | 持有三个组件（`HubertEncoder`/`RmvpeExtractor`/`Synthesizer`）、`l_linear` 系数缓存、`call_index`（噪声/文件的调用序号） |
| `vc(...)` | 单块：HuBERT → 可选检索 → ×2 最近邻 → protect → 噪声/SineGen → `synth.infer` → 裁 `x_pad*tgt_sr` |
| `run(...)` | 高通 → 切点搜索（内联）→ 反射 pad → 整段 f0 → 逐块 `vc` → 拼接 → RMS → 可选重采样 → int16 |

**调用顺序伪代码**（简化）：

```
run(audio):
    high_pass_48hz(audio)
    opt_ts = (n+160 > x_max*16000) ? 搜索低能量点 : []
    audio_pad = reflect_pad(audio, x_pad)
    f0 = rmvpe.infer(audio_pad)  # 变调/粗量化一次完成
    s = 0
    for t in opt_ts:  emit vc(audio_pad[s : t+2*x_pad+160], f0[s/160 : (t+2*x_pad)/160]); s = t
    emit vc(audio_pad[s : ], f0[s/160 : ])
    拼接 → apply_rms_mix → 可选 resample_mono → 峰值归一化 → int16
```

`vc()` 的细节（×2 最近邻、protect 公式、`pf = f0>=1 ? 1 : protect`）见文档三 §5.3。

### 6.2 `src/rvc/retrieval.{h,cpp}`

- `load()`：以 `GgufModel` 读取索引（`index.dim/nlist/ntotal/nprobe` 元数据 +
  `centroids/vectors/list_offsets/list_lengths` 四张 F32 张量），拷回主机后即可释放模型；
- `search()`：质心 L2² 取 `nprobe` 个列表 → 列表内全扫维护 top-k 最大堆 → 升序输出（同分按位置，保证确定性）；
- `blend()`：对每帧取 top-k（k=8），权重 `(1/score)²` 归一化加权，再
  `index_rate*mix + (1-index_rate)*feat`。调用点在 pipeline `vc()` 的 ×2 插值之前。

### 6.3 `src/rvc/sinegen.{h,cpp}`

主机端逐样本生成激励：相位累积 + `align_corners` 线性插值 + 回绕补偿，清音帧输出噪声；
噪声可由外部注入（验证模式）或固定种子生成。输出再由 pipeline 做 `tanh(l_linear*x+b)`。

## 十、关键设计与约定

| 设计 | 原因 |
|---|---|
| 每个模型类内部自持一个 `GgmlGraphRunner`，按输入形状缓存图 | 避免重复建图/分配；长度变化（长音频分块）自动重建 |
| 常量输入（相对位置嵌入、flip 矩阵、kernel 占位）在分配后一次性写入 | 这些张量每帧不变，避免每次推理重复上传 |
| 模型权重张量常驻后端缓冲；图缓冲由图分配器统一规划 | 权重跨多次推理复用；中间缓冲按图峰值需求分配 |
| `mul_mat` 是唯一矩阵乘入口，量化权重必须在 `src0` | 兼容 ggml 量化路径（CPU/Vulkan 的硬约束） |
| 卷积统一走 `im2col + mul_mat`（新布局） | 使卷积权重可量化；旧布局仍可走原生卷积 |
| 模型中张量统一 F32 输出；`[C,T]` 与 `[T,C]` 仅在边界转换 | 与上游算子语义（沿 `ne0` 的 norm/softmax）和量化路径对齐 |
| 验证模式通过注入参考噪声/参考 f0 实现逐样本对照 | 隔离随机性与 RMVPE argmax 翻转；`--noise-dir`/`--f0-inject` |
| 自检与正式推理复用同一代码路径 | 保证验证对象就是发布行为 |

## 十一、复杂部分与后续专项文档建议

以下部分当前只在本手册/文档三给出主干，若需要逐行级说明，建议各自成篇：

1. **VITS flow / WaveNet / 生成器**：条件切片广播、`res_skip` 通道分流、噪声卷积步长规则、
   `conv_transpose1d` 裁剪与输出对齐；
2. **RMVPE 窗口与 GRU 状态接力**：窗口对齐函数、keep 掩码在首帧/补帧时的语义、
   反向块与 head 的交错顺序；
3. **Vulkan matmul N 维切分补丁**（`patches/`）：视图偏移、禁用 split_k 的理由、
   与官方 M 切分的兼容；
4. **音频重采样器**：Kaiser 窗参数、分数延迟多相结构、与 soxr 的差异来源；
5. **相对位置注意力**：`relative_to_absolute/absolute_to_relative` 的索引推导与
   嵌入窗口展开（`expand_relative_embedding`）；
6. **量化策略**：导出脚本中各 `*_policy` 的完整规则表与回退逻辑；
7. **FAISS 索引转换**：IVF 列表布局、nprobe 语义与搜索顺序的确定性保证。
