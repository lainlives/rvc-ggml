# RVC-GGML 技术文档（一）：项目移植与实现概览

> 读者定位：不一定熟悉 C++，但了解 RVC 项目与语音转换（VC）原理的读者。
> 本文回答三件事：**这个重写项目是怎么推进的、各部分用什么思路实现、C++ 版与原版 Python 版有什么不同**。
> 文中不展示大段代码；具体实现细节见《技术文档（二）》。

---

## 一、项目目标与范围

### 1.1 一句话目标

把 RVC（Retrieval-based Voice Conversion，原版为 Python + PyTorch/WebUI 实现）的**离线推理**能力，
移植为一个**纯 C++ + ggml** 的独立可执行程序，通过 **Vulkan** 在 Intel / AMD / NVIDIA 显卡上加速（并提供 CPU 回退），
产出与原版**听感一致**的转换语音。

### 1.2 与原版功能对照

|功能|原版 RVC|RVC-GGML（本项目）|
|-|-|-|
|离线语音转换|✅ WebUI / CLI|✅ CLI + 交互式向导|
|特征提取|fairseq HuBERT / ContentVec|✅ 等价结构自实现|
|音高提取|pm / harvest / rmvpe / crepe 可选|✅ 仅 RMVPE|
|检索（特征混合）|FAISS IVF 索引|✅ 等价实现（读取同一索引数据）|
|合成器|VITS（SynthesizerTrnMs 256/768）|✅ v1(256) / v2(768)，f0 与非 f0 结构均实现|
|模型格式|.pth / .pt / .index|GGUF（含混合量化）|
|运行依赖|Python + torch + fairseq + faiss + librosa…|单 exe + 系统 Vulkan 驱动 + vcomp140.dll|
|训练 / 微调|✅|❌ 不做|
|实时变声（GUI/VST/ASIO）|✅|❌ 不做|
|UVR5 人声分离|✅|❌ 不做（输入需为已分离的人声）|
|TTS|✅|❌ 不做|

### 1.3 技术选型

* **语言**：C++20（MSVC / Visual Studio 2026 工具链，静态 CRT）
* **推理框架**：ggml 0.23（本地源码树），既作为张量/图运行时，也作为 Vulkan / CPU 后端。
  **注意：本项目修改了 ggml 源码**——Vulkan 后端矩阵乘新增 N 维切分（修复长音频/48 kHz 模型崩溃，
  见 6.4 与《技术文档（二）》§5.5）；补丁文件在 `patches/ggml-vulkan-matmul-n-split.patch`，
  从源码构建时必须使用打过补丁的 ggml，否则会复现运行期断言
* **后端**：Vulkan（默认 GPU）+ CPU 回退；CUDA 编译选项保留但非目标
* **模型格式**：GGUF（元数据 + 权重），支持 fp32/fp16/q8_0/q5_1/q4_1/q4_0 混合量化
* **输出目标**：Windows 10/11 x64 单目录绿色包（exe + 模型 + 依赖 DLL）

**为什么选 ggml**：它是 llama.cpp 生态的底层张量库，自带 Vulkan/CPU 后端、量化内核与跨 GPU 厂商的
着色器；与"离线推理 + 量化 + 跨显卡"的目标契合，且无需随包分发庞大的运行时。

## 二、原版 RVC 的推理链路（先对齐"要复刻什么"）

原版 RVC 一次转换的核心流程（`infer/modules/vc/pipeline.py` 等）：

1. **音频预处理**：任意格式/采样率 → 单声道 16 kHz；`scipy.signal.filtfilt` 实现 48 Hz 高通；
长音频按"低能量点"切块（`x_pad/x_query/x_center/x_max` 参数）。
2. **内容特征（HuBERT）**：16k 波形送入 fairseq HuBERT/ContentVec；v1 取第 9 层输出经 final_proj
投影到 256 维，v2 取第 12 层原始 768 维；输出为 50 fps 的特征序列。
3. **检索混合（可选）**：用 FAISS IVF 索引在训练集特征中找 top-k 近邻，
按 `index_rate` 与当前特征做加权混合（改善音色）。
4. **音高（f0）**：RMVPE 从 16k 音频估计基频（Hz），按半音变调系数缩放，
并量化为 1~255 的 pitch bin 供合成器查表。
5. **合成（VITS）**：

   * `enc_p`：特征 + pitch 查表 → 相对位置注意力编码 → 得到均值/方差（m_p/logs_p）；
   * 采样 z_p，经 `flow` 逆变换得到 z；
   * `dec`（HiFiGAN NSF）：用 SineGen 按 f0 生成谐波激励（f0 模型），与 z 一起合成波形；
   * **清音保护（protect）**：清音帧用原始特征替换；**RMS 混合**：按 `rms_mix_rate` 混合原音频响度。
6. **后处理**：拼接各块、可选重采样到 `resample_sr`、归一化并写 WAV。

运行依赖：Python、PyTorch、fairseq、faiss、librosa/scipy 等。

## 三、移植的总体推进流程

项目按"**先拆管道、再逐模型对齐、最后全链路**"的方式分阶段推进，每一阶段都有可自动化的
数值验收标准（与 Python 参考实现对比，相关系数 corr ≥ 0.999）：

|阶段|内容|验收|
|-|-|-|
|P0|音频管道：重采样 / 高通 / RMS / 静音切块|与 Python 逐样本对齐|
|P1|模型转换工具：四类 GGUF（hubert/rmvpe/角色/索引）|逐张量与源权重一致|
|P2|HuBERT 图|10 个中间阶段 corr ≥ 0.99999|
|P3|RMVPE 图|mel/显著性/f0 全部对齐|
|P4|VITS 图（enc_p/flow/dec + SineGen）|音频 corr ≥ 0.999999|
|P5|全链路管线 + 检索 + 长音频|端到端 corr ≥ 0.999，双后端|
|P6|交互式 CLI、混合量化、卷积量化、发布打包|全档位 Vulkan/CPU 可用|

**为什么要"逐阶段数值对齐"**：神经网络移植最怕"整体听不出问题、局部已经错了"。做法是让 Python 参考
在中间层把张量落盘（mel、卷积输出、注意力输出、m\_p/z、音频…），C++ 用相同输入跑出同层结果，
用相关系数/信噪比判定。这样任何一个算子写错都会在最早出现的阶段被抓住。

**参考实现对照**：除原版 RVC 外，还参考了社区已有的纯 ggml RVC 实现（0xShug0/audio.cpp，MIT）
的图组织方式；但本项目以原版 Python 行为为准。

## 四、各部分是怎么实现的（思路层面）

### 4.1 音频管道

* **多相 FIR 重采样**：替代 librosa（内部走 soxr）的任意采样率→16k；质量级一致（非逐样本）。
* **48 Hz 高通**：手工实现零相位 filtfilt（奇偶扩展 + 前后向滤波），修复后与 scipy **逐位一致**。
* **静音切块**：按 `x_pad/x_query/x_center/x_max`（秒）计算能量曲线上的最小值点；与 Python 相同公式。
* **RMS 曲线/混合**：按帧计算能量包络，`rms_mix_rate` 控制转换结果与原音频响度的混合比例。

### 4.2 模型格式（GGUF）与混合量化

* 用 Python 脚本把 `.pth/.pt/.index` 转成 GGUF：元数据（模型版本、采样率、层数、说话人数…）
与全部权重；PyTorch 张量形状与 ggml 的 `ne` 语义一致，**不做转置**。
* **混合量化**：对量化不敏感的大权重（注意力/前馈/卷积）量化；数值敏感部分（bias、LayerNorm/
BatchNorm、embedding、GRU、流耦合层、卷积转置等）保持 F32/F16。
* 关键约束与解决：ggml 量化张量的"行宽"必须是 32 的倍数，而卷积核宽度（3/7/10/11…）不满足，
导致**卷积原本无法量化**。本项目把卷积权重在导出时"展平"为行宽 = 输入通道×核面积的矩阵，
运行时用 im2col + 量化矩阵乘实现卷积（详见技术文档二）。

### 4.3 HuBERT（内容特征）

* 结构复刻：卷积前端（7 层，逐层降采样）→ LayerNorm → post\_extract\_proj → 位置卷积（带 GELU）→
LayerNorm → 12 层 Transformer（**Post-Norm** 结构）→ v1 取第 9 层 + final\_proj / v2 取第 12 层。
* 注意力实现为"逐头小矩阵乘"（多头拆分后在每头上做矩阵乘），与 PyTorch 语义一致且对 ggml 友好。
* 特征输出为 \[帧数, 256/768]，与 Python 行主序一致。

### 4.4 RMVPE（音高）

* 由四张子图组成：**mel 前端**（主机侧 FFT，滤波器组直接使用 GGUF 中的预计算表，与 librosa 一致）、
**DeepUnet 特征网络**（编码/中间/解码，含转置卷积上采样）、**双向 GRU**（前向/反向）、
**360 类显著性头**。
* GRU 在静态图中"展开"为固定长度序列，块与块之间用"状态接力"（保留掩码 + 最终隐状态）实现流式语义。
* f0 解码：argmax + 邻域加权平均（cents→Hz）+ 阈值判定清音。
* 长音频：整段推理（≤ 16352 帧，约 163.5 秒）与带上下文的窗口推理两级策略。
  该阈值由 Vulkan 矩阵乘的 N 维上限反推（修复前设 65536 帧，会在 >163.8 秒时触发断言；
  详见《技术文档（二）》§3.6 与 §5.5）。

### 4.5 检索（FAISS IVF 等价实现）

* 训练索引（`.index`）被转换为 GGUF：质心、每个倒排列表的向量/偏移/长度、nprobe 一并保存。
* 运行时按 FAISS 的 IVF 语义：用质心选 nprobe 个最近列表 → 在列表内暴力算 L2² 距离 → top-k →
以 `(1/score)²` 归一化权重混合特征，再按 `index_rate` 与原特征加权。
* 结果与 FAISS 原索引逐元素一致（参数 nprobe 必须随索引保存，这一点已修正）。

### 4.6 VITS（合成器）

* **enc_p**：`emb_phone`（线性）＋ `emb_pitch`（按 pitch bin 查表）→ 缩放 + LeakyReLU →
6 层 \[相对位置多头注意力 + LayerNorm + FFN(k=3) + LayerNorm] → proj 得到 \[2×inter, T]。
* **flow**：4 组耦合层逆变换，中间穿插"通道翻转"。翻转用 192×192 置换矩阵的矩阵乘实现（避免大量拼接）。
* **dec（HiFiGAN NSF）**：conv_pre → 4 级上采样（转置卷积）→ 每级叠加"激励噪声卷积"与 3 个残差块
→ LeakyReLU → conv_post → tanh。输出 40 kHz/48 kHz 波形。
* **SineGen**：主机侧按 f0 生成正弦谐波（随机相位由固定种子/注入噪声控制，保证可复现），
经 tanh(线性) 合并后作为激励。
* 布局：编码/流部分用 \[通道, 时间]（便于与线性层/注意力一致），生成器部分用 \[时间, 通道]（卷积自然序），
入口/出口做一次转置。

### 4.7 管线编排与长音频

* 与 Python 相同的顺序：高通 → 切块 → 每块 \[HuBERT → 检索 → ×2 最近邻上采样 → protect → VITS → 裁剪] →
拼接 → RMS 混合 → 可选重采样 → int16 归一化。
* 图按输入长度**缓存**：同一长度只建一次图；长度变化自动重建（与 Python 行为一致）。
* 生成随机噪声默认使用固定种子（每次运行结果可复现），便于对比。

### 4.8 设备与后端

* 启动时枚举 Vulkan 设备（`--list-devices`），可指定 `--device 0/1/...`；`--device 99` 强制 CPU。
* Vulkan 设备初始化失败或不可用时自动回退 CPU 并给出警告。
* 针对 Intel 驱动的两个已知问题默认启用规避（详见技术文档二）。

### 4.9 交互与命令行

* 无动作参数启动 → 单次向导：角色模型 → 量化档位 → 输入音频 → 设备 → 参数 → 确认转换。
* 同时保留完整命令行参数体系（`--input/--model/--quant/--pitch/--index...`），便于脚本化调用。

## 五、"原版以什么形式被重现"

核心原则：**公式与结构层面复刻，运行时整层替换；权重直接复用**。

1. **权重不变**：所有神经网络权重从原版 .pth/.pt 直接导出为 GGUF，数值一致（fp16/量化档位除外）。
2. **公式不变**：每一层的运算顺序、归一化位置、激活函数（含 GELU erf 精确版）、注意力缩放、
卷积 padding/裁剪、噪声注入方式均按原版复刻。
3. **流程不变**：切块策略、检索混合位置（×2 插值之前）、protect 语义、RMS 混合公式、归一化方式一致。
4. **运行时替换**：

   * torch/fairseq 的自动微分框架 → ggml 静态计算图；
   * FAISS → 自实现的 IVF 列表扫描；
   * librosa/scipy 的音频工具 → 自实现 DSP（重采样/高通/FFT）；
   * Python 运行时 → C++ 单进程。
5. **验证"重现"的方式**：同输入、同噪声、同 f0 下，C++ 与 Python 输出在音频层面 corr ≥ 0.999
（实测各链路 0.9991~0.9999，SNR 27~33 dB），差异主要来自浮点累积顺序与量化，而非算法。

## 六、C++/ggml 版与原版的主要区别

### 6.1 运行时与部署

|维度|原版|本项目|
|-|-|-|
|依赖|Python + torch + 多个 C 扩展|单 exe（+系统 Vulkan 驱动 + vcomp140.dll）|
|启动开销|解释器 + 模型加载（秒级）|进程启动 + 模型加载（百毫秒级）|
|显卡支持|取决于 PyTorch（CUDA/ROCm/DirectML…）|统一走 Vulkan，跨厂商|
|量化|原版无官方推理量化（多为 fp32/fp16）|GGUF 混合量化（fp16/q8_0/q5_1/q4_1/q4_0）|

### 6.2 数值与实现细节差异

* **精度**：Python 参考在 CPU 上部分算子使用 float64，本项目统一 float32；
部分卷积内部走 fp16 im2col，存在 \~1e-3 量级误差（听感无影响，验证阈值已按此设定）。
* **f0 的数值敏感性**：显著性 top1/top2 极接近时 argmax 会翻转（<0.1% 帧）。单个 f0 帧错误会让
SineGen 相位永久偏移，导致波形级对比掉相关，但**听感上仅是 10ms 的相位差**，不属于算法错误。
* **重采样**：原版 librosa(soxr) 与本项目多相 FIR 不是逐样本一致（质量级一致）；默认不重采样时不受影响。
* **随机噪声**：原版每次推理使用随机噪声；本项目默认固定种子（可复现），验证模式可注入参考噪声。
* **检索**：FAISS 的 SIMD 距离计算与自实现循环的结果在 float32 下可能有末位差异，混合权重一致。

### 6.3 功能差异

* 音高算法仅 RMVPE（不做 pm/harvest/crepe）。
* 不做训练/微调、实时变声、UVR5 分离、TTS。
* 输入要求：本地 WAV 文件；输出为 16-bit PCM 单声道 WAV。
* 不支持原版 WebUI 的"模型版本自动检测"外的一些边缘配置（如自定义 f0 曲线、harvest 参数等）。

### 6.4 对 ggml 源码的修改（重要）

本项目**不是直接使用官方 ggml**：本地 ggml 源码有一处必要修改，否则长音频会崩溃。

* **改了什么**：Vulkan 后端矩阵乘 `ggml_vk_mul_mat` 增加 **N 维切分**（官方实现只对超大 M 切分，
  N 维从不切分）。当 `N > maxComputeWorkGroupCount[1] × 32`（= 2,097,120）时按列分块计算；
  分块内禁用 split_k，并把原有 M 切分逻辑抽成公共函数复用。
* **为什么必须改**：Vulkan 规定 Y 方向 workgroup 数 ≤ 65535，矩阵乘按 `N/32` 分发。
  典型触发是 VITS 生成器末级卷积：`N = VITS 帧数 × hop`
  ——48 kHz 模型单块 > 43.7 s、40 kHz > 52.4 s、RMVPE 整段 > 163.8 s 就会触发
  `ggml-vulkan.cpp:8617` 断言（Intel 核显与 Arc 独显均可复现）。
* **补丁与重建**：补丁在 `patches/ggml-vulkan-matmul-n-split.patch`（应用方法见该目录 README）。
  FetchContent 拉取官方 ggml 时构建系统会自动应用补丁；本地 ggml 源码则构建时检测，
  检测不到会打印 WARNING，需手动应用；升级 ggml 源码后必须重新应用。
* **影响面**：纯 dispatch 划分，短音频/小模型数值与行为不变；Vulkan 路径生效，CPU 路径不受影响。
* 技术细节与验证记录见《技术文档（二）》§5.5。

## 八、已知限制与后续方向

1. **q4_0 质量下降较明显**：当前策略把生成器卷积也量化；后续可按听感实测调整（如生成器保持 F16）。
2. **长音频显存**：40s 级切块的 VITS 图缓冲可达 GB 级；后续做更细的块策略/复用。
3. **非 ASCII 路径**：模型路径含中文时 GGUF 加载会失败（ggml 按 UTF-8 打开文件，而 Windows 命令行
参数是本机 ANSI 编码）；音频路径不受影响。建议模型目录用英文，后续版本修复。
4. **32k / non-f0 模型**：结构上支持，但当前没有对应模型，未做实测。
5. 显存/量化进一步优化（如量化卷积的 im2col 缓存改 F16）留待下一阶段。
